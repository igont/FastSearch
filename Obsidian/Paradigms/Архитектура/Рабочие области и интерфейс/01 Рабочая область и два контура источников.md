# Рабочая область и два контура источников

[← Рабочие области и интерфейс](<00 Рабочие области и интерфейс.md>)

## Статус

Workspace-модель реализована как основной human runtime. Direct DT3 CLI с тремя путями сохранён только как совместимый operator/machine surface.

## Контекст

Пользователь исследует продукт или систему, а не три внутренних каталога FastSearch. Документация и код могут отсутствовать независимо и могут быть распределены по нескольким roots. Копия executable в каждом repository создаёт version drift и усложняет обновление.

## Парадигма

На машине устанавливается один FastSearch executable. Он хранит малый глобальный каталог известных рабочих областей, а каждая рабочая область имеет один canonical root и собственный `.fastsearch` namespace. Внутри области существуют ровно два класса источников:

- `documentation` — ноль или несколько roots, обрабатываемых document analyzers;
- `code` — ноль или несколько roots, обрабатываемых language analyzers.

Все document roots входят в один document namespace, все code roots — в один code namespace. Оба namespace публикуются через единый типизированный knowledge graph и единый query surface; различие алгоритмов распознавания и provenance не стирается.

## Состояния области

- Ноль настроенных контуров — область существует, поиск недоступен, интерфейс предлагает обнаружить или добавить источники.
- Только `documentation` — полноценный поиск и graph operations по документации.
- Только `code` — полноценный поиск и graph operations по коду.
- Оба контура — объединённый поиск, document/code filters и межграфовые связи.

Количество roots не меняет число контуров. Один и тот же physical root может быть допущен в оба контура и проходит два независимых analyzer pipeline.

## Границы

- Global catalog хранит только identity, canonical workspace path, display name, last-opened metadata и health hint; graph/index records остаются внутри workspace state.
- Source roots внутри workspace сохраняются относительно canonical root; внешний absolute root требует отдельного advanced admission.
- Automatic discovery формирует предложения, но не начинает тяжёлую индексацию до видимого подтверждения области.
- FastSearch не сканирует весь диск для восстановления потерянного global catalog.
- Копирование executable в каждый repository не является поддерживаемой основной моделью установки.

## Инварианты

- Ровно два source namespaces: `documentation` и `code`.
- Каждый root получает стабильный `root_id`; одинаковый relative path в разных roots не создаёт collision.
- Отсутствие одного контура не считается degraded state другого.
- Ноль контуров не выдаётся за готовую к поиску область.
- Один системный executable может открыть любую совместимую рабочую область.
- Global catalog можно потерять и восстановить повторным подключением workspace root без потери repository-owned knowledge.

## Связь с реализацией

`WorkspaceProfile`, `WorkspaceCatalog`, bounded discovery и workspace-конфигурация `ProductionRuntime` поддерживают multiple roots и 0/1/2 contours. Rooted stable IDs предотвращают collision одинаковых relative locators. Контракт подтверждают unit tests workspace store/discovery/catalog, `tests/workspace_runtime.rs` и human-flow tests в `tests/cli_ux.rs`. Advanced admission roots вне canonical workspace и перенос legacy external service state не входят в текущий baseline.
