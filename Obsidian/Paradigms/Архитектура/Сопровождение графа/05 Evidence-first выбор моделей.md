# Выбор поисковых моделей по доказательствам

## Исходное положение

Качество поиска нельзя назначить по названию модели или одному удачному запросу. Сравнение требует одинакового корпуса, проверяемых вопросов и независимо подготовленных ожидаемых результатов.

## Целевой продуктовый смысл

Обычный поиск использует один закреплённый продуктом набор моделей. Его состав меняется только после воспроизводимого сравнения качества и отдельного пересмотра технического решения. Пользователь и агент не выбирают модель для каждого запроса.

Экспериментальный режим остаётся отдельным инструментом исследования. Он показывает независимые выдачи допущенных моделей и не изменяет производственный набор автоматически.

## Пользовательский результат

Пользователь получает один общий список релевантных фрагментов, а не несколько блоков с несопоставимыми оценками. Изменение внутреннего состава поиска не должно менять форму команды или заставлять потребителя разбирать происхождение каждого результата.

## Границы обещания

Эталонный корпус и оценки подтверждают качество только в заявленной области запросов и источников. Режим сравнения не является обычным поиском, а его частичный результат не считается доказательством готовности производственного набора.

Точный, полнотекстовый и структурный поиск сохраняют самостоятельное назначение. Они не служат скрытой заменой неготового производственного семантического поиска.

## Инварианты

- Эталонные корпуса, вопросы и ожидаемые результаты версионируются.
- Качество оценивается по конкретным задачам, а не по одной суммарной метрике.
- Смена модели или её редакции делает соответствующую векторную проекцию устаревшей.
- Производственный набор моделей фиксирован и не настраивается на уровне запроса или рабочей области.
- Режим сравнения не изменяет производственный набор.
- Оценки разных embedding-моделей не объединяются напрямую в общий рейтинг.
- Готовность производственного поиска требует готовности всех обязательных моделей.

## Последствия

Каталог может содержать больше моделей, чем требуется обычному поиску. Для производственного запроса подготавливаются только закреплённые роли, а остальные варианты используются для исследований и будущей квалификации.

## Проверка соблюдения

Положение соблюдено, если производственная команда не принимает параметр модели, режим сравнения не меняет её поведение, а замена любой обязательной модели требует нового воспроизводимого сравнения и обновления связанного TDR.

## Отложенные вопросы

Новые модели рассматриваются только после появления основания пересмотреть закреплённый набор.

## Термины

Embedding-модель - модель, преобразующая запрос и фрагменты в векторы для поиска кандидатов. Производственный набор - закреплённые модели и их роли, обязательные для обычного семантического поиска.
