# Иерархический граф кода

[← Графы знаний](<00 Графы знаний.md>)

## Статус

Принята hierarchy code graph. Поддержка каждого языка проходит отдельную qualification и никогда не предполагается из наличия Tree-sitter grammar.

## Контекст

Список symbols без hierarchy и resolved relations не позволяет понять module responsibilities, class boundaries, callers и impact. Идентичность по byte offset ломается от форматирования и перестановки declarations.

## Парадигма

Code namespace единого knowledge graph строится как `root/repository → package/module → namespace → type/class/struct/trait → function/method/test`. Ноль или несколько code roots проходят language-specific analyzers; AST и resolver извлекают declarations, canonical signatures, inputs/outputs, imports, calls, inheritance, implementations, reads/writes и tests.

## Identity boundary

- Stable key использует stable `root_id`, relative module, containing scope, symbol name и canonical signature.
- Whitespace, comments, byte offsets и порядок declarations внутри неизменившегося scope не входят в identity.
- Изменение function body сохраняет node identity при неизменном symbol contract.
- Rename, signature change или перенос между modules может создать removed old node и added new node.
- Автоматическая поддержка переноса функции между modules намеренно не проектируется.

## Relations

Основные directed edge kinds: `CONTAINS`, `IMPORTS`, `CALLS`, `IMPLEMENTS`, `INHERITS`, `READS`, `WRITES`, `PROVIDES`, `CONSUMES`, `TESTS`. Edge хранится один раз; incoming и outgoing indexes обеспечивают двустороннюю навигацию.

## Инварианты

- Static exact, inferred dynamic и unresolved relations различаются.
- Parser error одного файла/языка снижает completeness и не обнуляет честный partial graph.
- Source locator не является stable identity.
- Anonymous/local symbols получают scope-bound identity и отдельную confidence.
- Structural fact не создаётся моделью, если его способен доказать language analyzer.
- Одинаковый relative locator в разных code roots не создаёт collision.

## Связь с реализацией

DT3 извлекает Rust/Python function/struct/class records через Tree-sitter, но их IDs включают position и relations почти отсутствуют. Target требует нового graph contract, per-language resolver и migration tests.
