# Полный граф через ограниченные запросы

[← Графы знаний](<00 Графы знаний.md>)

## Статус

Принят query contract, при котором полный graph revision доступен agent, но один response и стартовый context остаются bounded.

## Контекст

Передача всего графа в prompt переполняет контекст, а выдача только заранее выбранного slice не позволяет агенту исследовать неожиданную границу задачи. Нужна полная доступность без полной materialization.

## Парадигма

FastSearch принимает anchors, edge filters, direction, depth, budget и exact graph revision. Dtree обычно запрашивает initial impact subgraph, после чего агент самостоятельно вызывает neighbors, callers, callees, path, impact, documentation, source и semantic re-anchor с другой глубиной.

## Границы

- Ограничивается response nodes/edges/bytes/time, а не доступный graph namespace.
- Truncated response содержит boundary/continuation, а не молча неполный результат.
- Query может закрепить revision либо явно запросить current.
- Dtree хранит assignment query history; FastSearch возвращает query provenance и graph revision.
- Raw SQLite и physical graph tables не являются API.

## Инварианты

- Одинаковый query на одном revision даёт deterministic ordered result.
- Incoming/outgoing traversal не требует duplicated reverse edges.
- Unsupported edge kind и partial language coverage наблюдаемы.
- Agent может расширяться в сторону, вверх hierarchy или глубже по calls без нового context curator.
- Source snippets возвращаются по явному запросу и budget, а не всегда.

DT4 планирует MCP `search/get/related/status`, но graph traversal, impact radius, path и revision-pinned queries не входят в его scope и относятся к DT10.
