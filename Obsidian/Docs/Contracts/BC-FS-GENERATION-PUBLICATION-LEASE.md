# BC-FS-GENERATION-PUBLICATION-LEASE

Состояние: `BLOCKED`  
Версия: `1`  
Производитель: `FastSearch source/state generation coordinator`  
Прямые потребители: `application::public_search`, `application::thin_search lease release controller`, `FastSearch source/state writer`, `FastSearch runtime supervisor`

Машинный дескриптор: [BC-FS-GENERATION-PUBLICATION-LEASE.boundary.json](BC-FS-GENERATION-PUBLICATION-LEASE.boundary.json)

## Назначение и граница

Контракт единолично определяет линейризуемый допуск читателей захваченного поколения и writer публикации source/provenance state. Он не строит поисковую привязку и не формирует публичный ответ. `application::public_search` запрашивает lease только после полного provisional anchor state; `application::thin_search` освобождает его только после consume-once terminal; writer получает отдельный авторитетный допуск.

Текущая реализационная граница - один локальный процесс Windows. Linux и macOS имеют только точки расширения без реализации. Состояние lease не является общей SQLite-таблицей предметных модулей и не открывается внешнему клиенту.

## Авторитетное состояние

`GenerationPublicationLeaseState v1` принадлежит только generation coordinator, хранится в его disposable recovery ledger внутри `.fastsearch/local` и изменяется атомарно под тем же межпроцессным Windows lock, который допускает публикацию нового source/state generation. Каждый state, request, outcome, permit, replay и recovery key явно несёт одну `workspace identity`; совпадающие локальные ID разных workspace не взаимозаменяемы. Снимок содержит:

- `coordinator_instance_id`, монотонный `state_revision` и текущее `state_generation`;
- отображение `active_leases[lease_id] -> response_assembly_id + captured_generation + owner_process_identity + acquired_revision`;
- отображение `acquire_replays[response_assembly_id + captured_generation + owner_process_identity] -> lease_id + исходный ACTIVE_ACQUIRED outcome + ACTIVE|RELEASED|PROCESS_DIED + retained_until`;
- tagged union `released_identities[lease_id]`: `TERMINAL_RELEASE(committed_terminal_identity + idempotency_key + released_revision)` либо `PROCESS_DIED(owner_process_identity + cleanup_revision)`; эти варианты нельзя подменять друг другом;
- `active_writer_permit = NONE | writer_permit_id + writer_operation_id + owner_process_identity + previous_generation + baseline_bundle_identity + expected_revision + recovery_deadline`; permit является частью durable state, а не памятью writer-процесса;
- `writer_admission_replays[writer_operation_id] -> exact request identity + ACTIVE(writer_permit_id, GRANTED revision) | CLOSED(writer_permit_id, closure_ref)` и `writer_closure_replays[writer_permit_id] -> writer_operation_id + COMMITTED|ABORTED|RECOVERED_* + confirmed revision`; terminal closure атомарно переводит admission replay в `CLOSED`, поэтому запоздалый повтор не может воскресить permit;
- вычисляемый `writer_admission`, равный `GRANTED` тогда и только тогда, когда `active_leases` пусто и `active_writer_permit = NONE`.

`owner_process_identity` включает PID и время старта процесса, поэтому повторно использованный PID не наследует lease. Acquire/release replay хранится до завершения owning process и не меньше максимального retry/readback horizon. После crash следующий локальный процесс начинает с нового `coordinator_instance_id`, под exclusive lock повторно открывает опубликованное поколение и recovery ledger, авторитетно проверяет старые process identities и до любого writer admission переводит leases умерших владельцев в `PROCESS_DIED`. Повреждённый или непрочитанный ledger блокирует writer и не трактуется как пустой active set.

Открытие ledger всегда возвращает `NEVER_INITIALIZED|PRESENT|MISSING_PREVIOUS|CORRUPT|UNAVAILABLE`. Три failure-состояния до initial proposal дают `GenerationLeaseStateAccessBlocked`. Если то же состояние обнаружено при exact commit-recovery attempt, block дополнительно сохраняет retained pending proposal revision/digest и не создаёт новый proposal. Ни один вариант не является bootstrap, не трактуется как пустой active set и не выдумывает revision для `UNAVAILABLE`; writer остаётся заблокированным до будущего operator-recovery контракта. Только доказанный `NEVER_INITIALIZED` допускает fresh bootstrap.

Любой изменяющий переход сначала обязан получить пригодный authoritative lookup. `MISSING_PREVIOUS|CORRUPT|UNAVAILABLE` до proposal либо при exact recovery retained proposal создаёт только `GenerationLeaseStateAccessBlocked`. При пригодном lookup переход создаёт `ProposedLeaseState`, затем ledger атомарно записывает кандидат и возвращает закрытый `LeaseLedgerCommitReadback`: `COMMITTED_EXACT(revision + digest)`, `NOT_COMMITTED(previous_revision)` либо `UNKNOWN(stage + cause)`. Только `COMMITTED_EXACT` разрешает coordinator выдать внешний bootstrap/acquire/release outcome, writer permit/closure или cleanup. Для любого operation kind `NOT_COMMITTED|UNKNOWN` вместо предметного результата создаётся единый `GenerationLeaseCommitRecoveryStatus` с исходными operation identity и proposal revision/digest. Runtime supervisor производит только bounded `GenerationLeaseCommitRecoveryAttempt`; coordinator по нему повторно открывает authority и возвращает новый status, domain outcome либо exact access block. Эти три ветви для одного решения взаимоисключающие; две последние отказные ветви не доказывают lease, release, permit, cleanup либо writer closure.

## Acquire

`GenerationPublicationLeaseRequest v1` производит `application::public_search`: `workspace identity + response_assembly_id + captured_generation + owner_process_identity`. Coordinator одним переходом читает поколение и состояние lease только этого workspace:

- `ACTIVE_ACQUIRED` создаёт уникальный `lease_id`, добавляет запись в `active_leases` и возвращает `observed_generation + state_revision` только при `observed == captured`;
- `REPLAYED_TERMINAL` возвращает сохранённые `committed_terminal_identity + terminal_journal_ref + terminal_record_digest` без нового permit, публичного envelope или release; retention replay-указателя не превосходит retention адресованной terminal-записи;
- `REPLAYED_PROCESS_DIED` возвращает recovery-only outcome без нового permit и требует нового поиска, если результат всё ещё нужен;
- `CHANGED` возвращает точное observed generation, не создавая lease;
- `FAILED` возвращает stage/cause, не изменяя состояние и не подменяя результат `CHANGED`.

Повтор acquire с полной той же identity активного lease возвращает тот же `ACTIVE_ACQUIRED` и `lease_id`. После terminal release он возвращает `REPLAYED_TERMINAL`, после `PROCESS_DIED` - `REPLAYED_PROCESS_DIED`; эти outcomes намеренно отличаются от действующего permit. Повтор с тем же assembly, но другим generation или owner identity отклоняется без изменения состояния.

## Release и восстановление

`GenerationPublicationLeaseReleaseRequest v1` производит только `application::thin_search lease release controller` из durable consume-once terminal: `workspace identity + response_assembly_id + lease_id + committed_terminal_identity + idempotency_key + terminal_journal_ref + terminal_record_digest`.

- Для совпавшего active lease переход `ACTIVE -> RELEASED` применяется один раз, сохраняет replay-запись и возвращает `RELEASED + state_revision`.
- Точный повтор той же release identity возвращает `ALREADY_RELEASED` по replay-записи и не изменяет state.
- Неизвестный lease, несовпадающая assembly/terminal identity или чужой idempotency key возвращает `RELEASE_FAILED` без изменения любого lease.
- Операционный `RELEASE_FAILED` сохраняет исходный lease активным. Controller повторяет тот же запрос и readback с тем же ключом; после request deadline ответственность переходит `FastSearch runtime supervisor`, который продолжает bounded retry с backoff до `RELEASED|ALREADY_RELEASED` либо до доказанного завершения owning process.
- Если commit release-перехода не доказан, coordinator возвращает только `NOT_COMMITTED_RETRY|COMMIT_READBACK_REQUIRED|COMMIT_RECOVERY_BLOCKED`, а не `RELEASE_FAILED`, `RELEASED` или `ALREADY_RELEASED`. Thin search переводит первые два status в retryable `RECOVERY_REQUIRED`, а terminal `COMMIT_RECOVERY_BLOCKED` — в `RECOVERY_BLOCKED` без следующего release request; `CLOSED` разрешён только после авторитетного domain outcome, а независимый matching process-death cleanup может дать `PROCESS_DIED_CLOSED`.

Уже зафиксированный immutable public envelope разрешено передать адаптеру сразу после terminal commit: closure не меняет его содержимое. Невыполненный release блокирует только следующую writer publication и остаётся видимым диагностике; suppressed terminal внешнего envelope не создаёт.

## Writer admission и аварийная очистка

Writer не читает `active_leases` напрямую. Он передаёт `GenerationWriterAdmissionRequest v1` с устойчивым `workspace identity + writer_operation_id + owner_process_identity + coordinator_instance_id + expected state_revision + previous_generation + baseline_bundle_identity`. Exact replay durable-принятой `ACTIVE` операции возвращает тот же `GRANTED + writer_permit_id`; `CLOSED` возвращает `ALREADY_CLOSED + closure_ref` и не выдаёт capability повторно. `BLOCKED` разрешено повторно вычислить без записи только для того же `PRESENT` revision, а изменившийся revision даёт `RETRY_REQUIRED` и требует новой request identity. Новый identity допускается только для актуального снимка с пустым active set и отсутствующим active writer permit. Живой writer удерживает тот же ОС-lock до commit/abort публикации, поэтому новый acquire не вклинивается между проверкой и записью.

Каждая process-death command получает durable `ProcessDiedClosureAck v1` и несёт неизменную `workspace identity`: supervisor хранит delivery progress по `workspace + command_id`, а thin_search открывает только outbox этого workspace. При outbox `ABSENT` до OPEN сначала сохраняется `PREOPEN_PROCESS_DIED_CLOSED` tombstone без public terminal; для `OPEN` и `TERMINAL_COMMITTED(RELEASE_PENDING|RECOVERY_REQUIRED|RECOVERY_BLOCKED)` сохраняется обычное `PROCESS_DIED_CLOSED`. Запоздалая command после `CLOSED|PROCESS_DIED_CLOSED`, другой workspace или иная identity даёт `REJECTED_MISMATCH` без перехода и без `APPLIED`. `APPLIED` выдаётся только после outbox `COMMITTED_EXACT`, exact lost-ACK replay — `ALREADY_APPLIED` с той же полной workspace-scoped command identity и receipt. Supervisor завершает delivery progress только по `APPLIED|ALREADY_APPLIED`; `REJECTED_MISMATCH` оставляет доставку незавершённой и никогда не засчитывает sibling либо cross-workspace command.

`GRANTED` содержит непрозрачный `writer_permit_id`; прежде чем доставить его writer, coordinator durable-записывает permit и admission replay. Writer обязан вернуть `GenerationWriterPublicationOutcome v1`: `COMMITTED(writer_permit_id + writer_operation_id + previous_generation + published_generation + bundle_identity)` либо `ABORTED(writer_permit_id + writer_operation_id + stage + cause)`. Coordinator сверяет владение тем же lock: `COMMITTED` атомарно меняет `state_generation`, сохраняет bundle identity, очищает permit и записывает closure replay; `ABORTED` очищает permit без смены generation и также записывает closure replay. Только `COMMITTED_EXACT` readback выдаёт closure наружу. Exact повтор после потерянного ACK читает ту же closure; `NOT_COMMITTED|UNKNOWN` оставляет операцию в recovery и запрещает новый writer.

Потеря writer process освобождает прежний ОС-lock, но не удаляет durable permit. Recovery перед проверкой заново получает exclusive lock; persisted permit продолжает блокировать admission. Coordinator выпускает `DeadGenerationWriterRecoveryRequest`; runtime supervisor возвращает нумерованную bounded-попытку, а единственный авторитетный `source/state published bundle reader` - `COMMITTED_MATCH`, `NOT_COMMITTED` либо `AMBIGUOUS`. Первые два дают durable `RECOVERED_COMMITTED|RECOVERED_ABORTED`, closure replay и `CLOSED` admission replay. `AMBIGUOUS` сохраняет permit и блокирует новый writer до следующей попытки; по deadline получается `OPERATOR_ACTION_REQUIRED` с точными permit/operation, stage, cause, evidence bundle и state revision. Supervisor прекращает автоматические повторы и передаёт статус operator diagnostics; версия 1 не разрешает очистить permit или продолжить ветвь, пока отдельный operator-recovery контракт не будет принят. Угаданное поколение и бесконечный скрытый retry запрещены.

Windows process guard сообщает `ProcessLeaseOwnerDied v1` только для точной `PID + process_start_time`. Coordinator под exclusive lock удаляет все lease умершего владельца, сохраняет `PROCESS_DIED` replay-записи и после `COMMITTED_EXACT` формирует один durable cleanup batch с точной `workspace identity`. Removed entries сортируются лексикографически по `lease_id`; batch получает `cleanup_event_id`, а каждый элемент - stable `command_id + ordinal/count`. Coordinator создаёт ровно одну workspace-scoped `ProcessDiedReleaseClosureCommand` на removed lease, ноль для пустого списка; runtime supervisor доставляет команды независимо и при повторе сохраняет полную identity. Thin search принимает не более одной command на matching lifecycle: `OPEN|TERMINAL_COMMITTED(RELEASE_PENDING|RECOVERY_REQUIRED|RECOVERY_BLOCKED)` durable-закрывается как `PROCESS_DIED_CLOSED`, `ABSENT` получает только `PREOPEN_PROCESS_DIED_CLOSED` tombstone, а `CLOSED|PROCESS_DIED_CLOSED` не меняется. Ни одна ветвь не изображает `RELEASED|ALREADY_RELEASED`. Linux/macOS cleanup остаётся `NOT_IMPLEMENTED`.

## Цепочка данных

`complete AnchorAssemblyState -> acquire request -> ProposedLeaseState -> COMMITTED_EXACT readback -> ACTIVE_ACQUIRED|REPLAYED_TERMINAL|REPLAYED_PROCESS_DIED|CHANGED|FAILED -> FinalizedAnchorAssembly, authoritative terminal-journal readback, recovery-only outcome или pre-lease failure -> durable consume-once response terminal -> release request -> ProposedLeaseState -> COMMITTED_EXACT readback -> RELEASED|ALREADY_RELEASED|RELEASE_FAILED -> CLOSED, RECOVERY_REQUIRED либо PROCESS_DIED_CLOSED`. Независимо writer проходит `typed ledger lookup/bootstrap -> writer_operation_id -> durable active_writer_permit + admission replay -> GRANTED|ALREADY_CLOSED|BLOCKED|RETRY_REQUIRED -> publish только для GRANTED -> durable COMMITTED|ABORTED closure replay либо dead-writer recovery -> confirmed generation closure, RECOVERY_REQUIRED или terminal OPERATOR_ACTION_REQUIRED`. Для любой state-changing операции `NOT_COMMITTED|UNKNOWN -> GenerationLeaseCommitRecoveryStatus -> same-operation lookup/readback | terminal BLOCKED`; usable domain outcome отсутствует. Bootstrap outcome отдельно передаётся bootstrap owner, writer closure - writer и supervisor. `ALREADY_CLOSED` возвращает прежнюю closure без публикации, `RETRY_REQUIRED` требует нового lookup и request identity.

Ни public search, ни runtime supervisor не создают `state_revision`, active set или replay-записи. Они получают только типизированные outcomes от coordinator. Потерь данных на acquire/release границе нет; диагностический consumer может скрыть terminal payload, но сохраняет lease identity, state revision и cause.

## Приёмка

Контракт принимается после реализации одного coordinator и проверок: закрытый lookup union `NEVER_INITIALIZED|PRESENT|MISSING_PREVIOUS|CORRUPT|UNAVAILABLE` на всех surface, приоритетный `GenerationLeaseStateAccessBlocked` для каждого operation kind, запрет любых proposals для трёх blocked-состояний и terminal block без выдуманного операторского recovery, матрицу `bootstrap|acquire|release|writer admission|writer closure|writer recovery|process cleanup × COMMITTED_EXACT|NOT_COMMITTED|UNKNOWN` с единым commit-recovery handoff и без orphan capability, G1 acquire, generation mismatch, duplicate acquire в active/terminal/process-died состояниях, authoritative terminal-journal replay после G1 -> G2, concurrent A+B, release A при активном B, exact duplicate и mismatched terminal/key, операционный release failure с controller-to-supervisor handoff, writer permit и `ACTIVE|CLOSED` admission replay durable до выдачи `GRANTED`, delayed admission replay после commit/abort с `ALREADY_CLOSED` без публикации, `RETRY_REQUIRED` с новым lookup/request identity, exact `writer_operation_id` во всех closure, separate bootstrap and writer-closure handoff, duplicate commit/abort, crash до/после bundle publication и closure ACK, освобождение старого и reacquire нового Windows lock при recovery, `COMMITTED_MATCH|NOT_COMMITTED|AMBIGUOUS` recovery и terminal operator escalation без дальнейшего auto-retry или права очистить permit, PID reuse, workspace-scoped coordinator -> supervisor -> thin_search disposition для `ABSENT|OPEN|TERMINAL_COMMITTED`, коллизию одинаковых assembly/lease/command ID в двух workspace после restart, stale command после `CLOSED`, новый coordinator instance после restart и гонки acquire/release/writer под реальным Windows lock. Все outcomes сверяются независимым state-machine oracle; публичный runtime отдельно доказывает, что delivery после terminal не зависит от release latency, а writer зависит.

## Блокеры

- Схемы state/request/outcome, bootstrap, writer admission/closure replay и coordinator ещё не реализованы.
- Нет Windows process guard и runtime supervisor recovery loop.
- Нет независимого concurrency oracle и доказательства реального writer lock.
- Нет принятого операторского recovery-контракта для `MISSING_PREVIOUS|CORRUPT|UNAVAILABLE|OPERATOR_ACTION_REQUIRED`; версия 1 только останавливает ветвь и сохраняет evidence.
