# BC-FS-MCP-STDIO. MCP через стандартные потоки

## Состояние и версия

Контракт имеет версию `1` и состояние `DRAFT`. Протокол и реализация определены, но реальный обмен ещё не оформлен как граничное доказательство для точной принятой редакции.

## Производитель и ответственность

Производителем является `adapters::mcp`. Адаптер владеет протокольным циклом MCP, схемой единственного инструмента `search`, ограниченной очередью, отменой и преобразованием публичного ответа в результат инструмента.

## Среда исполнения и платформенные порты

Текущая среда - локальный процесс Windows. Обязательные порты - `stdin` для входящих MCP-сообщений, `stdout` только для протокола и `stderr` для безопасной диагностики. Linux и macOS имеют определённую точку расширения, но не входят в текущую приёмку.

## Потребители и назначение передачи

Потребитель - внешний MCP-клиент, запускающий `fastsearch mcp --workspace <абсолютный-каталог>`. Он согласует версию протокола, обнаруживает инструмент и получает структурированный поисковый результат без доступа к внутренним моделям и индексам.

## Входные данные и авторитетные источники

Вход процесса содержит абсолютный путь рабочей области. Вход инструмента содержит поля `query`, `project_scope` и `document_status` по `BC-FS-PUBLIC-SEARCH`. Принятая версия протокола - `2025-11-25`.

## Выходные данные и происхождение

Успех содержит структуру `PublicSearchResponse`. Ожидаемый прикладной отказ содержит `error { code, message, retryable }` и `isError: true`. Ошибка протокола применяется только к неверному циклу, неизвестному инструменту или недопустимой структуре MCP.

## Преобразования и потери

Адаптер декодирует аргументы в `PublicSearchRequest` и кодирует готовый публичный DTO в MCP без смыслового изменения. Диагностическая причина остаётся внутри процесса в соответствии с публичным поисковым контрактом.

## Цепочка поставки данных

MCP-клиент запускает процесс, `rmcp` обслуживает транспорт, `adapters::mcp` проверяет вызов и передаёт задание единственному владельцу `ThinSearchCoordinator`. Ответ возвращается через тот же адаптер клиенту; `stdout` не содержит иных сообщений.

## Отказы и восстановление

Третий одновременный вызов получает `BUSY`. Превышение 30 секунд даёт `TIMEOUT`, отменённый результат подавляется, закрытие `stdin` завершает процесс. Потеря рабочего потока или паника завершает сервер, после чего клиент запускает новый процесс.

## Условия передачи и приёмки

До вызова `search` клиент завершает `initialize -> notifications/initialized`. Несовместимая версия прекращает соединение до обычных операций. Запрос не создаёт рабочую область, не скачивает модели и не перестраивает проекции.

## Контрактные и интеграционные испытания

Исходные проверки находятся в `tests/dt4_mcp_thin_slice.rs` и модульных тестах адаптера. Для `ACCEPTED` требуется отчёт реального `stdio`-обмена с клиентом, включая успешный ответ, ошибки, очередь, отмену, EOF и чистоту `stdout`.

## Блокеры

Смысловой блокер отсутствует. Не собран связанный с редакцией отчёт интеграционного испытания.
