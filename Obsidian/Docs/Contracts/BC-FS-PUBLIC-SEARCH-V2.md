# BC-FS-PUBLIC-SEARCH-V2. Публичный поиск с точной привязкой

## Состояние и версия

Контракт имеет версию `2` и состояние `BLOCKED`. Он является совместимым преемником [BC-FS-PUBLIC-SEARCH v1](BC-FS-PUBLIC-SEARCH.md), а не скрытым изменением действующей формы. Версия 1 остаётся базовой поверхностью DT4; версия 2 материализуется только в DT13-A.

## Производитель и ответственность

Единственный производитель внешних `PublicSearchResponse v2`, `PublicSearchError v2` и ошибки переговоров - `application::thin_search` (`ThinSearchCoordinator`). Negotiation и base failure до появления ranked bundle возвращаются напрямую: у них ещё нет `response_assembly_id`, lease или частичного списка. С момента появления ranked bundle координатор владеет durable response lifecycle outbox, и только подтверждённая запись журнала делает post-bundle terminal, delivery, release request или recovery token наблюдаемыми. `application::public_search` остаётся отдельным производителем только вложенного `SearchSourceAnchorOutcome v1`.

## Выбор версии

MCP сохраняет имя метода `search`, но запрос v2 обязан явно передать `response_version: "2"`; отсутствие поля означает v1. CLI использует эквивалентный явный `--response-version 2`, а без флага сохраняет v1. Координатор получает отдельную authoritative capability `V1_ONLY|V1_V2_READY`, связанную с released producer build и digest схемы. Exact v2 запускается только при `V1_V2_READY`; иначе до базового поиска возвращается `PUBLIC_SEARCH_V2_NOT_READY`, а default/explicit v1 остаются рабочими. Неизвестная версия отклоняется как `UNSUPPORTED_RESPONSE_VERSION`. Молчаливое повышение v1 до v2 и удаление v1 без отдельного TDR и major-release решения запрещены.

## Входные данные и источники истины

- До поиска адаптер передаёт координатору сырой `ResponseVersionRequest v1`: поле отсутствует либо содержит строку. Координатор выбирает v1 для отсутствующего поля или `"1"`, v2 только для `"2"`, а любое другое значение отклоняет без ranked bundle и outcomes.
- Успешный поиск производит единый внутренний `RankedCanonicalResultBundle v1`. Каждая позиция содержит непрозрачный уникальный внутри assembly `position_id`, `record_id + captured state_generation` и базовые `rank/title/path/project_scope/document_status/content`; `position_id` не равен rank, не публикуется в wire и служит только для внутренней корреляции.
- Для каждой канонической записи `application::public_search` в том же поколении производит ровно один `SearchSourceAnchorOutcome v1`: `READY` с полной привязкой либо `BLOCKED` с типизированной `SearchSourceAnchorError v1`.
- Вся сборка имеет одну `workspace identity + response_assembly_id`; `application::public_search` передаёт их и captured generation владельцу [generation publication lease](BC-FS-GENERATION-PUBLICATION-LEASE.md). Coordinator возвращает ровно одну из трёх взаимоисключающих workspace-scoped ветвей: предметный outcome `ACTIVE_ACQUIRED|REPLAYED_TERMINAL|REPLAYED_PROCESS_DIED|CHANGED|FAILED` после durable confirmation; generic commit-recovery status `NOT_COMMITTED_RETRY|COMMIT_READBACK_REQUIRED|COMMIT_RECOVERY_BLOCKED`, если commit proposal не доказан; либо typed `GenerationLeaseStateAccessBlocked`, если authoritative ledger потерян, повреждён или недоступен. Только `ACTIVE_ACQUIRED` создаёт полный `FinalizedAnchorAssembly v1` и отдельный `AnchorPublicationPermit v1`; две отказные ветви не доказывают ни наличие, ни отсутствие lease и потому не могут создать permit, no-lease terminal или release.
- До lease permit общий response lifecycle принимает correlated `CANCELLED|TIMEOUT`. Если событие выигрывает CAS в `ASSEMBLING`, provisional state уничтожается и lease не запрашивается. Если lease уже `PENDING`, termination ждёт authoritative ветвь: `ACTIVE_ACQUIRED` машинно создаёт finalized wrapper, отдельный permit и pending-acquired termination с точными `permit_id + response_assembly_id + lease_id`; `CHANGED|FAILED` завершает assembly без lease; replay-ветви не создают новый permit или envelope; commit-recovery status продолжает same-operation recovery, а terminal commit/access block переводит assembly в `RECOVERY_BLOCKED` без no-lease terminal. После `FINALIZED` termination всегда сверяется с тремя полями.
- `FastSearch response lifecycle outbox store` авторитетно возвращает `ABSENT|OPEN|TERMINAL_COMMITTED|PREOPEN_PROCESS_DIED_CLOSED|CORRUPT|UNAVAILABLE` и для каждой предложенной записи - `COMMITTED_EXACT|NOT_COMMITTED|UNKNOWN`. `TERMINAL_COMMITTED` для persisted release-derived `CLOSED|RECOVERY_REQUIRED|RECOVERY_BLOCKED` дополнительно возвращает byte-identical последний closure proposal revision/digest и встроенное полное `response_entry_mode_evidence`: workspace, assembly, закрытый variant, process epoch, lifecycle attempt и proposal/commit либо terminal/restart-intent identity. Это самодостаточное immutable значение, а не ссылка на отдельное хранилище. `RELEASE_PENDING` такого перехода ещё не имеет, а `PROCESS_DIED_CLOSED` вместо mode хранит command identity. Любая pre-lease terminal-ветвь сначала делает exact lookup: только `ABSENT` без revision разрешает предложение terminal с `lease_scope = NONE`; `TERMINAL_COMMITTED` переигрывается, `OPEN` даёт `PRELEASE_OPEN_REPLAY_REQUIRED`, `PREOPEN_PROCESS_DIED_CLOSED` является tombstone без public terminal для process-death command, пришедшей после active lease, но до OPEN; `CORRUPT|UNAVAILABLE` ведут в bounded recovery. Потеря ACK разрешается тем же lookup/readback без восстановления состояния по текущему поколению.
- `application::thin_search` через response lifecycle entry dispatcher для каждого live-выбора current-epoch terminal confirmation либо existing-terminal carrier reconstruction создаёт ровно один закрытый `ResponseLifecycleEntryMode v1`: `INITIAL_COMMIT_CONFIRMATION` с identity proposal/commit attempt в текущей process epoch XOR `RESTART_READBACK` с authoritative terminal revision/digest, детерминированным `restart_readback_identity`, exact `restart_intent_ref`, lifecycle entry attempt и новой process epoch. Restart intent является ровно одним replay/resume-сигналом либо повторно доставленным ответом release coordinator. Persisted-closure readback и command-only process-death replay не создают live mode: первый проверяет встроенное `response_entry_mode_evidence`, второй — command identity. Отдельная durable запись work item не требуется: сохранённый `TERMINAL_COMMITTED` row и сам redelivered response дают authority на восстановление. Один lookup в одной attempt не может обслужить оба производимых режима. Режим управляет только выбором carrier-ветви и не меняет stable release identity.
- Базовый отказ поиска является отдельным `BaseSearchFailure v1` и не требует ranked bundle или outcomes.

Путь и rank не используются для восстановления `record_id`, generation или selector. Отложенный выбор читает уже сериализованный outcome.

## Выходной формат

`PublicSearchResponse v2` является закрытым JSON-объектом:

- `contract_id = "fastsearch.public-search"`;
- `contract_version = "2"`;
- `query`, `count`, `results` с прежними пределами DT4;
- каждый `PublicSearchResult v2` сохраняет `rank`, `title`, `path`, `project_scope`, `document_status` и `content` v1;
- `path` остаётся локальным полем показа и никогда не входит в межпродуктовую identity;
- каждый result содержит обязательный закрытый `anchor_outcome` ровно одной формы:
  - `{"status":"READY","anchor":{...SearchSourceAnchor v1...}}` без `error`;
  - `{"status":"BLOCKED","error":{...SearchSourceAnchorError v1...}}` без `anchor`.

Both/neither, лишние поля, несовместимые status/payload и разные поколения внутри одного ответа запрещены. Граница потребителя является закрытым объединением `PublicSearchResponse v2 | PublicSearchError v2`: ошибка не смешивается с per-result `anchor_outcome`, не содержит списка результатов и запрещает извлечение anchor либо вызов FastGraph; клиент сохраняет typed code и указанного владельца восстановления.

`PublicSearchError v2` является отдельным закрытым JSON-объектом ровно из пяти полей: `contract_id = "fastsearch.public-search-error"`, `contract_version = "2"`, `code`, `recovery_owner`, `recovery_action`. Карта закрыта семью значениями: `INVALID_REQUEST -> CALLER / CORRECT_REQUEST`, `NOT_READY -> FASTSEARCH_READINESS / RESTORE_READINESS`, `STALE_INDEX -> FASTSEARCH_SOURCE_STATE / REBUILD_SOURCE_STATE`, `BUSY -> CALLER / RETRY_SEARCH`, `TIMEOUT -> CALLER / RETRY_SEARCH`, `RESPONSE_TOO_LARGE -> CALLER / REFINE_REQUEST`, `SEARCH_FAILED -> FASTSEARCH_SOURCE_STATE / INSPECT_DIAGNOSTICS`. `results`, `anchor_outcome`, внутренние permit/assembly/lease и дополнительные поля запрещены.

## Цепочка передачи

`сырой ResponseVersionRequest -> проверка поддерживаемой версии -> для exact 2 проверка V1_V2_READY -> только затем base readiness/search -> RankedCanonicalResultBundle одного поколения и response_assembly_id -> INIT/accumulate AnchorAssemblyState -> pre-permit termination либо lease request -> ровно один durable lease domain outcome, commit-recovery status или typed ledger-access block -> FinalizedAnchorAssembly + stable AnchorPublicationPermit, terminal replay, recovery-only outcome или один pre-lease failure -> authoritative response outbox ABSENT|OPEN|TERMINAL_COMMITTED|PREOPEN_PROCESS_DIED_CLOSED|CORRUPT|UNAVAILABLE -> proposed OPEN/TERMINAL/PREOPEN tombstone либо exact replay/recovery -> COMMITTED_EXACT -> PublicResponseAssemblyTerminal либо pre-open command receipt`. Post-permit terminal допускается только из exact `OPEN(outbox_revision)`; pre-lease terminal - только из `ABSENT` без revision; pre-open tombstone не является terminal.

После обычного подтверждённого terminal immutable response/error разрешено передать CLI/MCP, а leased terminal сохраняет одну release identity. `PublicResponseAssemblyTerminal` является только immutable уведомлением первого commit и несёт `initial_closure_state`; текущая closure принадлежит authoritative `TERMINAL_COMMITTED` row и отдельному `GenerationLeaseClosureOutcome`. Только событие первого обычного terminal `COMMITTED_EXACT` создаёт первичный release request; exact restart/readback проходит отдельный replay-continuation, поэтому два selectors взаимоисключающие. Release-операция возвращает ровно одну из трёх ветвей: domain outcome `RELEASED|ALREADY_RELEASED|RELEASE_FAILED`; generic commit-recovery status; либо typed ledger-access block с полной release/lookup/optional proposal identity. Только первые два domain outcome доказывают `CLOSED`; `RELEASE_FAILED|NOT_COMMITTED_RETRY|COMMIT_READBACK_REQUIRED` сохраняют committed terminal и retryable `RECOVERY_REQUIRED`. `COMMIT_RECOVERY_BLOCKED` либо `GenerationLeaseStateAccessBlocked` немедленно запрещает следующий release request и предлагает durable `RECOVERY_BLOCKED` вместе с полным typed `blocked_evidence`; до его `COMMITTED_EXACT` разрешено только same-proposal response-outbox commit/readback recovery. Outbox digest покрывает closure и evidence, а commit/readback либо restart идемпотентно воспроизводит тот же `PublicSearchRecoveryBlocked` для supervisor, diagnostics и request owner. Writer остаётся заблокированным; отдельный matching process-death cleanup всё ещё может доказать `PROCESS_DIED_CLOSED`. Process-death cleanup является durable batch: coordinator сортирует removed leases по `lease_id` и создаёт ровно одну stable command с `workspace identity + cleanup_event_id + command_id + ordinal/count` на каждый removed lease; supervisor сохраняет delivery progress по `workspace + command_id`, доставляет их независимо, а thin_search открывает outbox только этого workspace и принимает не более одной command на lifecycle. Для `ABSENT` до OPEN command фиксирует tombstone `PREOPEN_PROCESS_DIED_CLOSED` без permit/public terminal/envelope/release; для `OPEN` фиксирует `COMMITTED_SUPPRESSED + PROCESS_DIED_CLOSED`; для committed terminal разрешён переход только из `RELEASE_PENDING|RECOVERY_REQUIRED|RECOVERY_BLOCKED`. `CLOSED|PROCESS_DIED_CLOSED`, другой workspace или несовпавшая identity дают `REJECTED_MISMATCH` без перехода и без `APPLIED`; supervisor не завершает delivery progress. Во всех трёх успешных случаях outbox сохраняет полную workspace-scoped identity команды и только после `COMMITTED_EXACT` thin_search возвращает `ProcessDiedClosureAck/APPLIED`. Exact replay после потерянного ACK возвращает `ALREADY_APPLIED` с тем же receipt. Пустой batch даёт ноль commands. Generation ledger и response outbox остаются разными authority без общей БД и cross-store lock.

Ответ любой release-ветви замыкается на ровно один immutable carrier исходной release identity: первичный `PublicResponseAssemblyTerminal` XOR `ReplayedGenerationLeaseContinuation` после restart. Carrier обязательно сверяется с authoritative `TERMINAL_COMMITTED` row. Domain outcome, generic commit-recovery status и typed state-access block принимают оба взаимоисключающих пути; повторно доставленный после crash coordinator response сам является restart intent и восстанавливает continuation из terminal row без `FinalizedAnchorAssembly` и permit. Ни один путь не требует повторного выпуска initial terminal. Поэтому `terminal committed -> crash -> restart -> ALREADY_RELEASED` достижимо завершает closure как `CLOSED`, а аналогичные restart-ветви `RELEASED|RELEASE_FAILED`, commit-recovery и state-access block сохраняют свои обычные правила.

Взаимоисключение carrier обеспечивается не догадкой по outbox state, а внутренним выходом `ResponseLifecycleEntryMode`. `INITIAL_COMMIT_CONFIRMATION` разрешает только первое подтверждение terminal и primary release; `RESTART_READBACK` разрешает только existing-terminal readback и resume release. Proposal/commit attempt либо детерминированная identity из authoritative terminal revision/digest, `restart_intent_ref`, `process_epoch_identity` и `lifecycle_entry_attempt_identity` делают выбор проверяемым. Initial terminal несёт `initial_entry_mode_ref`, replay continuation — `restart_entry_mode_ref`; все три обработчика ответа release-координатора сверяют carrier, mode и authoritative row, копируют полный mode как встроенное `response_entry_mode_evidence` в closure proposal и включают каждое его поле в digest. В той же process epoch live-confirm повторно принимает byte-identical mode. После crash отдельный persisted-readback transition читает это самодостаточное значение и digest из authoritative `TERMINAL_COMMITTED` без эфемерных proposal/mode outputs старой epoch и дополнительного хранилища; новый противоположный mode не может перепривязать или переписать proposal. Если commit не доказан, отсутствующий либо несовпавший mode не меняет closure. Process-death closure остаётся отдельной взаимоисключающей ветвью по exact command identity и не содержит response mode. Один lookup не может создать оба carrier или два transport request.

## Отказы и восстановление

Сначала разбирается `response_version`: неизвестное значение даёт `UNSUPPORTED_RESPONSE_VERSION`; absent/1 остаётся v1; exact 2 при `V1_ONLY` до любых base readiness/search checks даёт `PUBLIC_SEARCH_V2_NOT_READY`; только `V1_V2_READY` открывает семикодовую карту `PublicSearchError v2`. Pre/post-permit `CANCELLED` и post-permit `COMMIT_FAILED` создают suppressed terminal без публичного ответа. Post-permit termination применяется только при точном равенстве permit/assembly/lease с durable `OPEN` и `FinalizedAnchorAssembly`; mismatch не потребляет permit и уходит в durable bounded recovery.

`NOT_COMMITTED|UNKNOWN` после outbox write требуют readback; до `COMMITTED_EXACT` запрещены delivery, release, token, closure и `PublicResponseAssemblyTerminal`. `CORRUPT|UNAVAILABLE` имеют приоритет и обрабатываются только общими reject-переходами; pre-lease/replay transforms для них отключены. Для response-outbox и acquire recovery первичный failure создаёт `RETRY_REQUIRED`, а внутренний `PublicSearchRecoveryBlocked` возникает только после supervisor `EXHAUSTED`; terminal остаётся отсутствующим до доказанного commit. Для generation-release scope terminal уже существует и сохраняется неизменным: `COMMIT_RECOVERY_BLOCKED` либо `GenerationLeaseStateAccessBlocked` сразу создаёт operation-level `PublicSearchRecoveryBlocked`, запрещает release retry и предлагает durable `RECOVERY_BLOCKED`; неизвестный commit этой proposal восстанавливается только через response-outbox. Exact `TERMINAL_COMMITTED` replay копирует authoritative `lease_scope`: `NONE` остаётся без continuation, `lease_id` сохраняет прежнюю release/closure identity; если acquire replay уже несёт `released_revision`, но outbox остался `RELEASE_PENDING|RECOVERY_REQUIRED`, continuation повторяет только исходный same-key release до `ALREADY_RELEASED -> CLOSED`. Это не новая логическая release-операция. `RECOVERY_BLOCKED` после restart не возобновляет release и ждёт только exact matching process-death closure. Generic release commit status никогда не превращается в `RELEASED|ALREADY_RELEASED`. Operator repair protocol в v1 не согласован.

Восстановление выполняется явным повтором v2 после подготовки provenance или обычным запросом v1, если пользователю нужен только базовый поиск. Fallback никогда не маскируется под успешное графовое продолжение.

Отдельные restart-fixtures обязаны провести через replay-continuation carrier каждую ответную ветвь координатора: `RELEASED`, `ALREADY_RELEASED`, `RELEASE_FAILED`, каждый generic release commit-recovery status и release state-access block. Для каждой ветви проверяется crash после получения ответа, но до его consume: redelivery создаёт `RESTART_READBACK` и continuation без finalized assembly/permit. Отдельный fixture проводит `release COMMITTED в generation ledger -> crash до CLOSED в response outbox -> acquire REPLAYED_TERMINAL(released_revision) -> same-key ALREADY_RELEASED -> CLOSED`. Для ACK отдельно проверяется `stale command after CLOSED -> REJECTED_MISMATCH`: acknowledgement существует, содержит expected/actual evidence, но не создаёт transition или `APPLIED`.

Негативный selector-fixture подаёт один и тот же `TERMINAL_COMMITTED` lookup в одну lifecycle entry attempt и доказывает, что закрытый `ResponseLifecycleEntryMode` допускает только initial carrier + primary request либо replay carrier + resumed same-key request, но никогда оба carrier или два transport request. Отдельный crash-fixture `terminal COMMITTED_EXACT -> crash до dispatch -> новая epoch` выводит `RESTART_READBACK` только из retained terminal revision/digest и exact restart intent, затем доставляет response и продолжает release без потерянного work item. Ещё два fixture падают после release-derived closure proposal: `NOT_COMMITTED|UNKNOWN` плюс opposite mode дают ноль closure outcome, а authoritative `TERMINAL_COMMITTED` с persisted closure transition подтверждает исходное полное mode evidence отдельным post-crash transform без старых outputs, дополнительных lookup и нового `OUT-RESPONSE-LIFECYCLE-ENTRY-MODE`. Этот сценарий проверяется для `CLOSED`, `RECOVERY_REQUIRED` и `RECOVERY_BLOCKED`; новый mode не перепривязывает запись. Process-death proposal принимается отдельно по command identity без response mode.

## Блокеры

- `PublicSearchRequest/Result/Response v2` и штатная схема не реализованы.
- MCP и CLI не реализуют явные переговоры версии ответа.
- `SearchSourceAnchorOutcome v1` и source/provenance rebuild остаются `NOT_IMPLEMENTED`.
- Durable response lifecycle outbox, его typed lookup/commit readback, replay journal и supervisor recovery loop не реализованы.
- Операторский repair-контракт для terminal outbox corruption/unknown readback после bounded recovery не согласован; версия 1 только сохраняет evidence и блокирует дальнейшее действие.
