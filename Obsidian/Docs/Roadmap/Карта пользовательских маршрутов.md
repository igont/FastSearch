# FastSearch - карта пользовательских маршрутов

## Границы

Результат: пользователь передаёт один запрос в выбранной рабочей области и получает единый список из 0-6 уникальных фрагментов либо явный типизированный выход без частичной выдачи.

Точки входа: обычный текст в открытой области, `fastsearch search "<запрос>"` с необязательными фильтрами и `--json`, а также MCP `search` после запуска `fastsearch mcp --workspace <абсолютный-каталог>`. Восстановление выполняется только явными командами настройки источников, подготовки моделей и обслуживания индекса.

Не входит: явно выбранные точный, полнотекстовый и структурный режимы, сравнение моделей, графовое расширение FastGraph, действия над отдельным результатом и скрытая подготовка внутри поискового запроса. Принятые результаты DT2 и DT3 сохраняют прежние публичные точки входа и не пересматриваются этой картой.

Текущий фронт - фундаментальный контракт DT4-C, который разблокирует маршрут `FS_SEARCH_EXECUTE`. Остальные маршруты показывают необходимый горизонт восстановления, публичных представлений и выпуска, но не становятся ветвями первого исполняемого плана.

Карта задаёт целевое поведение DT4, а дорожная карта показывает его поставку. Наличие идентификатора не означает, что маршрут уже реализован: текущие расхождения производственного координатора с каноническими фактами закрываются в DT4-C, публичные переходы - в DT4-D, поставляемое подключение - в DT4-E.

## Владельцы поставки

| Маршруты | Производитель | Приёмочный владелец |
|---|---|---|
| `FS_WORKSPACE_OPEN`, `FS_SEARCH_CONFIGURE_SOURCES` | Принятая среда рабочих областей до DT4 | Действующие проверки `WorkspaceCatalog`, `WorkspaceStore` и терминальных переходов |
| `FS_SEARCH_PREPARE_MODELS` | Принятая граница DT4-B | Проверки согласованного снимка четырёх ролей и восстановления |
| `FS_SEARCH_REBUILD_PROJECTIONS`, `FS_SEARCH_UPDATE_PROJECTIONS`, `FS_SEARCH_EXECUTE` | DT4-C | Техническая приёмка производственного поиска, состояния и отказов |
| `FS_SEARCH_RETRY`, `FS_SEARCH_CANCEL`, `FS_SEARCH_REFINE_REQUEST` | DT4-D | Приёмка естественного ввода, CLI, JSON и MCP |
| `FS_RELEASE_CONNECT` | DT4-E | Выпускная приёмка из чистого каталога |

## Факты состояния

| Факт | Значения | Источник истины |
|---|---|---|
| Объект поиска | одна доступная область; область не выбрана; несколько кандидатов; область недоступна | [`WorkspaceCatalog` и `WorkspaceStore`](../../../src/application/workspace.rs), аргумент `--workspace` |
| Вход и запрос | допустимы; некорректный запрос или фильтр; несовместимый MCP-клиент | [`PublicSearchRequest`](../../../src/application/public_search.rs), CLI-маршрутизатор и согласование MCP |
| Источники | настроен хотя бы один контур; контуры не настроены; корень недоступен | `WorkspaceStore` и `.fastsearch/workspace.toml` по TDR-FS-2.1 |
| Корпус | `CURRENT`; `STALE`; `DEGRADED`; `NOT_CONFIGURED` | [`LifecycleStatus`](../../../src/domain/status.rs) и каноническое поколение `ProductionRuntime` |
| Модельный набор | четыре роли одного поколения готовы; набор отсутствует, повреждён или смешан | Один полностью проверенный [`ModelSetReadySnapshot`](../../../src/application/model_readiness.rs); его обязательное чтение входит в DT4-C |
| Векторные проекции | три проекции текущего поколения; отсутствуют; поколения различаются; устарели или повреждены | [`ProductionRuntime::model_partition_status`](../../../src/application/production/model_partitions.rs) и поколение корпуса |
| Ресурсы поиска | допуск по памяти выполнен; памяти недостаточно; рабочий предел превышен | [`ThinSearchCoordinator`](../../../src/application/thin_search.rs) и измеритель рабочего набора |
| Очередь MCP | свободна; один запрос выполняется; один выполняется и один ожидает | [`ThinMcpServer`](../../../src/adapters/mcp.rs) |
| Текущий вызов | отсутствует; выполняется; ожидает; отменён | MCP-контекст вызова и принадлежащий ему признак отмены |
| Выпуск | не получен; подтверждён исполняемый файл, контрольная сумма и инструкция; происхождение не подтверждено | выпускная квитанция DT4-E |

## Маршруты

Строки каждого намерения проверяются сверху вниз. Применяется первое совпавшее условие. Перед каждым принятым поисковым вызовом координатор заново открывает `WorkspaceStore`, проверяет один `ModelSetReadySnapshot`, поколение корпуса и три проекции; переход `FS_SEARCH_RETRY` возвращает разрешение к первой строке намерения `ПОИСК_ПОЛУЧИТЬ_РЕЗУЛЬТАТЫ` без перезапуска MCP-процесса.

## Контракты сложных маршрутов

### FS_SEARCH_EXECUTE

Изменение: постоянное состояние не меняется. Маршрут атомарно проверяет один снимок четырёх модельных ролей, читает одно поколение корпуса и трёх проекций, получает кандидатов от трёх закреплённых моделей, удаляет повторы, переранжирует общий набор и формирует один `PublicSearchResponse`.

Доказательство: независимый оракул подтверждает 0-6 уникальных фрагментов, последовательные номера, поля, порядок и содержимое. JSON и MCP семантически равны, консоль показывает тот же результат с русскими подписями.

Повтор и восстановление: повтор заново открывает все канонические факты. Смена источника или поколения до завершения даёт `BLOCKED / STALE_INDEX`; отмена имеет маршрутный выход `CANCELLED` без добавления кода `PublicSearchErrorCode`, а MCP подавляет ответ отменённого вызова. Истечение 30 секунд даёт `FAILED / TIMEOUT`, превышение размера ответа - `FAILED / RESPONSE_TOO_LARGE`, иной безопасно ограниченный сбой - `FAILED / SEARCH_FAILED`. Последующие входы явно ведут к обслуживанию, освобождению ресурсов, `FS_SEARCH_REFINE_REQUEST` или безопасному повтору. Частичный список не публикуется.

### FS_SEARCH_CONFIGURE_SOURCES, FS_SEARCH_PREPARE_MODELS, FS_SEARCH_REBUILD_PROJECTIONS и FS_SEARCH_UPDATE_PROJECTIONS

Изменение: каждый маршрут меняет только принадлежащее ему состояние. Настройка сохраняет допущенные корни, подготовка публикует согласованный модельный снимок, а обслуживание атомарно приводит три проекции к одному поколению корпуса.

Доказательство: после действия источник истины перечитывается новым поисковым вызовом, включая уже запущенный MCP-процесс. Повтор готового действия возвращает `ALREADY_DONE`; ошибка сохраняет последнее подтверждённое состояние и даёт `FAILED` либо `BLOCKED` с точным входом восстановления.

### FS_SEARCH_CANCEL

Изменение: текущий вызов помечается неактуальным, ожидающая работа прекращается на безопасной границе, а поздний результат подавляется. Корпус, проекции и модели не изменяются.

Доказательство: отменённый идентификатор не получает публичного ответа, после чего новый вызов обслуживается той же средой. Повтор без активного вызова возвращает `ALREADY_DONE`.

### FS_SEARCH_REFINE_REQUEST

Изменение: пользователь заменяет запрос либо один из двух фильтров; корпус, модели и проекции не меняются. Если предел превышает один неизбежный фрагмент, маршрут останавливается до исправления источника владельцем корпуса.

Доказательство: новый запрос заново проходит общие ограничения, а успешный сериализованный ответ не превышает 131072 байта. Повтор прежнего ввода не выдаётся за восстановление.

### FS_RELEASE_CONNECT

Изменение: поставляемый Windows-артефакт запускается как локальный MCP-процесс с выбранной рабочей областью. Внутреннее состояние поиска не создаётся и не перестраивается скрыто.

Доказательство: контрольная сумма и происхождение относятся к точной редакции, совместимый клиент завершает инициализацию и видит только `search`, после чего воспроизводит маршрут `FS_SEARCH_EXECUTE`.

## Контрольные пути

| Сценарий | Последовательность | Конечный результат |
|---|---|---|
| Готовая область и допустимый запрос | `FS_WORKSPACE_OPEN -> FS_SEARCH_EXECUTE` | `SUCCESS`, 0-6 результатов |
| Область не выбрана | `NEEDS_CHOICE -> FS_WORKSPACE_OPEN -> FS_SEARCH_EXECUTE` | Выбранный объект и `SUCCESS` |
| Источники не настроены, модели уже готовы | `BLOCKED -> FS_SEARCH_CONFIGURE_SOURCES -> FS_SEARCH_REBUILD_PROJECTIONS -> FS_SEARCH_RETRY` | `SEARCH_READY`, затем `SUCCESS` |
| Модельная роль не готова | `BLOCKED -> FS_SEARCH_PREPARE_MODELS -> FS_SEARCH_RETRY` | Готовый набор, затем `SUCCESS` либо следующий точный блок |
| Индекс устарел | `BLOCKED / STALE_INDEX -> FS_SEARCH_UPDATE_PROJECTIONS -> FS_SEARCH_RETRY` | Новое согласованное поколение и `SUCCESS` |
| Очередь заполнена | `BLOCKED / BUSY -> FS_SEARCH_RETRY` | Новый вызов после освобождения места |
| Запрос отменён | `FS_SEARCH_CANCEL` | `CANCELLED`, состояние поиска сохранено |
| Ответ превышает предел | `FAILED / RESPONSE_TOO_LARGE -> FS_SEARCH_REFINE_REQUEST -> FS_SEARCH_EXECUTE` | Ограниченный ответ либо точный `BLOCKED` на исправление источника |
| Выпуск из чистого каталога | `FS_RELEASE_CONNECT -> FS_SEARCH_EXECUTE` | Подключённый инструмент воспроизводит `USR-FS-03` |
