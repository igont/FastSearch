# FastSearch - карта пользовательских маршрутов

## Границы

Результат: пользователь передаёт один запрос в выбранной рабочей области и получает единый список из 0-6 уникальных фрагментов либо явный типизированный выход без частичной выдачи.

Точки входа: обычный текст в открытой области, `fastsearch search "<запрос>"` с необязательными фильтрами и `--json`, а также MCP `search` после запуска `fastsearch mcp --workspace <абсолютный-каталог>`. Восстановление выполняется только явными маршрутами настройки источников, подготовки моделей, provenance/индекса, generation lease и response outbox; поисковый запрос не запускает их скрыто.

Не входит: явно выбранные точный, полнотекстовый и структурный режимы, сравнение моделей, выполнение графового обхода FastGraph и скрытая подготовка внутри поискового запроса. Условный DT13 добавляет только передачу выбранной поисковой привязки следующему владельцу; сам обход остаётся отдельным маршрутом FastGraph. Принятые результаты DT2 и DT3 сохраняют прежние публичные точки входа и не пересматриваются этой картой.

Текущий фронт - фундаментальный контракт DT4-C, который разблокирует маршрут `FS_SEARCH_EXECUTE`. Остальные маршруты показывают необходимый горизонт восстановления, публичных представлений и выпуска, но не становятся ветвями первого исполняемого плана.

Карта задаёт целевое поведение DT4, а дорожная карта показывает его поставку. Наличие идентификатора не означает, что маршрут уже реализован: текущие расхождения производственного координатора с каноническими фактами закрываются в DT4-C, публичные переходы - в DT4-D, поставляемое подключение - в DT4-E.

## Владельцы поставки

| Маршруты | Производитель | Приёмочный владелец |
|---|---|---|
| `FS_WORKSPACE_OPEN`, `FS_SEARCH_CONFIGURE_SOURCES` | Принятая среда рабочих областей до DT4 | Действующие проверки `WorkspaceCatalog`, `WorkspaceStore` и терминальных переходов |
| `FS_SEARCH_PREPARE_MODELS` | Принятая граница DT4-B | Проверки согласованного снимка четырёх ролей и восстановления |
| `FS_SEARCH_REBUILD_PROJECTIONS`, `FS_SEARCH_UPDATE_PROJECTIONS`, `FS_SEARCH_EXECUTE` | DT4-C | Техническая приёмка производственного поиска, состояния и отказов |
| `FS_SOURCE_PROVENANCE_REBUILD` | DT13-A | Атомарная публикация новой source/provenance schema до перестроения поисковых проекций |
| `FS_SEARCH_EXECUTE_V2` | DT13-A | Переговоры Public Search v1/v2, exactly-one anchor outcome и независимый consumer |
| `FS_GENERATION_LEASE_RECOVER` | DT13-A release controller + runtime supervisor | Полная release identity, bounded retry/readback, terminal recovery и writer block до authoritative closure |
| `FS_RESPONSE_OUTBOX_RECOVER` | DT13-A `application::thin_search` lifecycle + runtime supervisor | Авторитетный outbox readback, terminal replay и bounded переход к operator-owned stop без повторной сборки ответа |

| `FS_SOURCE_ANCHOR_HANDOFF` | DT13-A производит привязку; DT13-B поставляет клиентскую композицию | Раздельная приёмка производящей пары FastSearch, потребляющей пары FastGraph и сквозного клиента |

## Факты состояния

| Факт | Значения | Источник истины |
|---|---|---|
| Объект поиска | одна доступная область; область не выбрана; несколько кандидатов; область недоступна | [`WorkspaceCatalog` и `WorkspaceStore`](../../../src/application/workspace.rs), аргумент `--workspace` |
| Вход и запрос | допустимы; некорректный запрос или фильтр; несовместимый MCP-клиент | [`PublicSearchRequest`](../../../src/application/public_search.rs), CLI-маршрутизатор и согласование MCP |
| Источники | настроен хотя бы один контур; контуры не настроены; корень недоступен | `WorkspaceStore` и `.fastsearch/workspace.toml` по TDR-FS-2.1 |
| Корпус | `CURRENT`; `STALE`; `DEGRADED`; `NOT_CONFIGURED` | [`LifecycleStatus`](../../../src/domain/status.rs) и каноническое поколение `ProductionRuntime` |
| Модельный набор | четыре роли одного поколения готовы; набор отсутствует, повреждён или смешан | Один полностью проверенный [`ModelSetReadySnapshot`](../../../src/application/model_readiness.rs); его обязательное чтение входит в DT4-C |
| Векторные проекции | три проекции текущего поколения; отсутствуют; поколения различаются; устарели или повреждены | [`ProductionRuntime::model_partition_status`](../../../src/application/production/model_partitions.rs) и поколение корпуса |
| Версии публичного ответа | `V1_ONLY`; `V1_V2_READY`; запрошена неподдерживаемая версия | Будущий `PublicSearchResponseVersionCapability v1`, который `ThinSearchCoordinator` строит из встроенного registry схем и readback adapter capability; `NOT_IMPLEMENTED` до DT13-A |
| Source/provenance bundle | `LEGACY_SCHEMA`; `CURRENT`; `MISSING`; `CORRUPTED` | Будущий `SourceProvenanceStateSnapshot v1`: schema marker, canonical generation, record count и provenance count/digest, прочитанные source-state reader под общей блокировкой; `NOT_IMPLEMENTED` до DT13-A |
| Generation lease ledger | `NEVER_INITIALIZED`; `PRESENT`; `MISSING_PREVIOUS`; `CORRUPT`; `UNAVAILABLE` | Единственный `GenerationPublicationLeaseState` coordinator; lost/corrupt/unavailable ledger не равен пустому active set и не допускает bootstrap или proposal |
| Writer publication recovery | `NONE`; `RECOVERY_REQUIRED`; `OPERATOR_ACTION_REQUIRED` | Подтверждённый ledger state и авторитетный source/state bundle reader; runtime supervisor только планирует bounded retry |
| Response lifecycle outbox | `ABSENT`; `OPEN`; `TERMINAL_COMMITTED`; `PREOPEN_PROCESS_DIED_CLOSED`; `CORRUPT`; `UNAVAILABLE`; commit `UNKNOWN` | Отдельный durable outbox `application::thin_search`; `PREOPEN_PROCESS_DIED_CLOSED` хранит только disposition и receipt exact process-death command без permit, terminal, envelope или release; terminal, delivery, release, tombstone и recovery token видимы только после `COMMITTED_EXACT`; unavailable lookup не изображает `ABSENT` |
| Ресурсы поиска | допуск по памяти выполнен; памяти недостаточно; рабочий предел превышен | [`ThinSearchCoordinator`](../../../src/application/thin_search.rs) и измеритель рабочего набора |
| Очередь MCP | свободна; один запрос выполняется; один выполняется и один ожидает | [`ThinMcpServer`](../../../src/adapters/mcp.rs) |
| Текущий вызов | отсутствует; выполняется; ожидает; отменён | MCP-контекст вызова и принадлежащий ему признак отмены |
| Выпуск | не получен; подтверждён исполняемый файл, контрольная сумма и инструкция; происхождение не подтверждено | выпускная квитанция DT4-E |
| Поисковая привязка | отсутствует; точная для одного поколения; устарела; неподдерживаемая версия | [BC-FS-SEARCH-SOURCE-ANCHOR](<../Contracts/BC-FS-SEARCH-SOURCE-ANCHOR.md>); пока `BLOCKED` до DT13-A |
| Внешнее разрешение | потребляющая пара FastGraph отсутствует; root mapping отсутствует; совместимый профиль готов | Каноническая будущая пара FastGraph и конфигурация композиционного клиента; FastSearch не является источником истины |

## Маршруты

Строки каждого намерения проверяются сверху вниз. Применяется первое совпавшее условие. Перед каждым принятым поисковым вызовом координатор заново открывает `WorkspaceStore`, проверяет один `ModelSetReadySnapshot`, поколение корпуса и три проекции; переход `FS_SEARCH_RETRY` возвращает разрешение к первой строке намерения `ПОИСК_ПОЛУЧИТЬ_РЕЗУЛЬТАТЫ` без перезапуска MCP-процесса.

|---|---|---|---|---|---|

| `ОБЛАСТЬ_ОТКРЫТЬ` | «Открой проект» | Область не определена или кандидатов несколько | `NEEDS_CHOICE` | Состояние не изменено; показаны кандидаты и один вопрос о выборе | `ОБЛАСТЬ_ОТКРЫТЬ` |

| `ПОИСК_ПРОДОЛЖИТЬ_ПО_ГРАФУ` | выбор найденного результата | В опубликованном `PublicSearchResult v2` привязка отсутствует, не имеет typed root/locator/raw hash захваченного поколения либо расходится с записью | `BLOCKED / SOURCE_PROVENANCE_UNAVAILABLE` или `SOURCE_PROVENANCE_MISMATCH` | FastSearch не создаёт ослабленную привязку и называет необходимость нового поиска или DT13-A | `ПОИСК_ПОЛУЧИТЬ_РЕЗУЛЬТАТЫ` после восстановления |
| `ПОИСК_ПРОДОЛЖИТЬ_ПО_ГРАФУ` | выбор результата с существующей привязкой | Версия или селектор не поддерживаются композиционным клиентом либо потребляющим профилем FastGraph | `BLOCKED / UNSUPPORTED_SOURCE_ANCHOR` | Базовая выдача и привязка не изменены; названы несовместимая сторона и поддерживаемые версии | выбрать совместимый клиент/контракт либо выполнить новый поиск после обновления производителя |
| `ПОИСК_ПРОДОЛЖИТЬ_ПО_ГРАФУ` | выбор результата с существующей привязкой | Эталонный потребитель или FastGraph прочитал по сопоставленному корню байты, чей SHA-256 не равен `raw_source_sha256` | `BLOCKED / STALE_SOURCE_ANCHOR` | Базовая выдача и неизменяемая привязка сохранены; FastSearch не переписывает уже выданное поколение | новый поиск после обновления корпуса, затем повторная передача |
| `ПОИСК_ПРОДОЛЖИТЬ_ПО_ГРАФУ` | выбор результата с точной привязкой | Потребляющая пара FastGraph, root mapping или композиционный клиент отсутствуют | `BLOCKED / GRAPH_RESOLVER_UNAVAILABLE` | Привязка не изменена; назван внешний владелец недостающей готовности | после готовности FastGraph или клиента повторить передачу |
| `ПОИСК_ПРОДОЛЖИТЬ_ПО_ГРАФУ` | выбор результата с точной привязкой | Производящая и потребляющая пары приняты, версии совместимы, клиент готов | `FS_SOURCE_ANCHOR_HANDOFF` | Клиент получает `SearchSourceAnchor v1` без graph node identity | следующий владелец: FastGraph resolve-anchor, затем GraphProvider traverse |
| `ИНСТРУМЕНТ_ПОДКЛЮЧИТЬ` | «Подключи FastSearch к MCP-клиенту» | Выпуск отсутствует или его происхождение не подтверждено | `BLOCKED` | Подключение не началось; запрошен проверенный выпуск | получить выпуск DT4-E |
| `ИНСТРУМЕНТ_ПОДКЛЮЧИТЬ` | запуск MCP-клиента | Версия протокола несовместима | `BLOCKED` | Поисковые операции не начались; показана поддерживаемая версия | новое совместимое соединение либо CLI |
| `ИНСТРУМЕНТ_ПОДКЛЮЧИТЬ` | запуск из чистого каталога | Артефакт подтверждён, путь области абсолютный, клиент совместим | `FS_RELEASE_CONNECT` | Клиент запускает поставляемый файл и видит единственный инструмент `search` | `ПОИСК_ПОЛУЧИТЬ_РЕЗУЛЬТАТЫ` |

## Контракты сложных маршрутов

### FS_SEARCH_EXECUTE

Изменение: постоянное состояние не меняется. Маршрут атомарно проверяет один снимок четырёх модельных ролей, читает одно поколение корпуса и трёх проекций, получает кандидатов от трёх закреплённых моделей, удаляет повторы, переранжирует общий набор и формирует один `PublicSearchResponse`.

Доказательство: независимый оракул подтверждает 0-6 уникальных фрагментов, последовательные номера, поля, порядок и содержимое. JSON и MCP семантически равны, консоль показывает тот же результат с русскими подписями.

Повтор и восстановление: повтор заново открывает все канонические факты. Смена источника или поколения до завершения даёт `BLOCKED / STALE_INDEX`; отмена имеет маршрутный выход `CANCELLED` без добавления кода `PublicSearchErrorCode`, а MCP подавляет ответ отменённого вызова. Истечение 30 секунд даёт `FAILED / TIMEOUT`, превышение размера ответа - `FAILED / RESPONSE_TOO_LARGE`, иной безопасно ограниченный сбой - `FAILED / SEARCH_FAILED`. Последующие входы явно ведут к обслуживанию, освобождению ресурсов, `FS_SEARCH_REFINE_REQUEST` или безопасному повтору. Частичный список не публикуется.

### FS_SEARCH_CONFIGURE_SOURCES, FS_SEARCH_PREPARE_MODELS, FS_SEARCH_REBUILD_PROJECTIONS и FS_SEARCH_UPDATE_PROJECTIONS

Изменение: каждый маршрут меняет только принадлежащее ему состояние. Настройка сохраняет допущенные корни, подготовка публикует согласованный модельный снимок, а обслуживание приводит lexical и три векторные проекции к одному уже принятому canonical generation. Эти маршруты не меняют schema marker, canonical records или provenance index.

Доказательство: после действия источник истины перечитывается новым поисковым вызовом, включая уже запущенный MCP-процесс. Повтор готового действия возвращает `ALREADY_DONE`; ошибка сохраняет последнее подтверждённое состояние и даёт `FAILED` либо `BLOCKED` с точным входом восстановления.

### FS_SOURCE_PROVENANCE_REBUILD

Изменение: единственный source-state writer под эксклюзивной блокировкой заново читает допущенные исходные байты и строит кандидат `schema_marker + canonical generation + records + provenance index` с typed root, полным selector payload, byte ranges и raw SHA-256. Один commit атомарно заменяет source/provenance bundle. Lexical и три векторные проекции не входят в этот commit и после него считаются устаревшими до отдельного `FS_SEARCH_REBUILD_PROJECTIONS` того же поколения.

Доказательство: readback под reader lock видит либо полностью старый, либо полностью новый source/provenance bundle. Crash до commit сохраняет прежний bundle; crash после commit и до проекций даёт `NOT_READY`, но не смешанный принятый поиск. Синтетический raw hash, частичный импорт старой схемы и публикация `SEARCH_READY` до совпадения всех поколений запрещены.

### FS_SEARCH_EXECUTE_V2

Изменение: тот же производственный поиск DT4 при явном `response_version = 2` сохраняет все базовые поля и порядок v1, захватывает одно поколение и добавляет к каждому результату ровно один `anchor_outcome`. Отсутствующая версия выбирает только v1; неизвестная версия отклоняется до поиска.

Доказательство: JSON и MCP семантически совпадают для закрытого union `PublicSearchResponse v2 | PublicSearchError v2`, независимый клиент отвергает both/neither outcome, а при внешнем error не извлекает anchor и не вызывает FastGraph; запрос без версии воспроизводит прежний v1. Per-result `BLOCKED` сохраняет базовые поля, но не выдаётся за готовность графового продолжения. Publication lease закрывает интервал от авторитетной проверки поколения до consume-once terminal; stable permit и exact outbox replay доказывают восстановление после потерянного ACK без новой identity. Поздняя смена G1 -> G2 создаёт один внешний `STALE_INDEX` без partial response, а недоступный coordinator или допустимый post-bundle assembly failure дают один безопасный terminal error. Внешний outcome попадает в wire только из `FinalizedAnchorAssembly -> application::thin_search -> PublicSearchResponse v2`.

### FS_SEARCH_CANCEL

Изменение: текущий вызов помечается неактуальным, ожидающая работа прекращается на безопасной границе, а поздний результат подавляется. До lease request отмена CAS-завершает assembly и уничтожает provisional state без lease. Для `LEASE_PENDING` pending `CANCELLED|TIMEOUT` ждёт одну authoritative ветвь: `ACTIVE_ACQUIRED` переводит её в post-permit branch того же lease; `CHANGED|FAILED` завершает без lease; replay не создаёт новый permit; `NOT_COMMITTED_RETRY|COMMIT_READBACK_REQUIRED` сохраняет pending event и exact acquire/proposal identity; `COMMIT_RECOVERY_BLOCKED|GenerationLeaseStateAccessBlocked` поглощает pending event через отдельный pending-aware переход и переводит assembly в `RECOVERY_BLOCKED` без ложного no-lease terminal. Thin_search и supervisor получают exact evidence. После permit фиксируется suppressed terminal и запускается идемпотентное закрытие lease; публичный ответ не отправляется. Корпус, проекции и модели не изменяются.

Доказательство: отменённый идентификатор не получает публичного ответа, после чего новый вызов обслуживается той же средой. Повтор без активного вызова возвращает `ALREADY_DONE`.

### FS_GENERATION_LEASE_RECOVER

Изменение: маршрут сначала различает закрытый union `NEVER_INITIALIZED|PRESENT|MISSING_PREVIOUS|CORRUPT|UNAVAILABLE`. Для каждой state-changing операции coordinator возвращает ровно одну из трёх ветвей: domain outcome после `COMMITTED_EXACT`; `NOT_COMMITTED_RETRY|COMMIT_READBACK_REQUIRED|COMMIT_RECOVERY_BLOCKED`, если commit proposal не доказан; либо typed `GenerationLeaseStateAccessBlocked`, если авторитетный ledger потерян, повреждён или недоступен до proposal либо при восстановлении retained proposal. Ветви взаимоисключающие; generic status и access block не создают permit, release acknowledgement или closure. Только `RELEASED|ALREADY_RELEASED` закрывает lease. После crash повторно доставленный coordinator response вместе с retained terminal row восстанавливает exact restart mode и carrier без finalized assembly/permit. Acquire `REPLAYED_TERMINAL(released_revision)` при незакрытом response outbox повторяет только прежний same-key release до `ALREADY_RELEASED -> CLOSED`. Generation coordinator единолично сортирует removed leases и создаёт stable command с `workspace identity + cleanup_event_id + command_id + ordinal/count` на каждый элемент; supervisor хранит delivery progress по `workspace + command_id`, повторяет прежние commands и никогда не делает второй fan-out либо cross-workspace lookup. Уже committed response/error не переписывается; writer остаётся `BLOCKED` до доказанного closure.

Доказательство: матрица `operation kind × PRESENT/NEVER_INITIALIZED/MISSING_PREVIOUS/CORRUPT/UNAVAILABLE × COMMITTED_EXACT|NOT_COMMITTED|UNKNOWN` не оставляет orphan lease/permit/cleanup. Lost ACK exact release после доказанного commit возвращает `ALREADY_RELEASED`; crash до consume каждой из трёх release-response ветвей восстанавливает её по exact restart intent; acquire replay после уже выполненного release доводит response outbox до `CLOSED`. Bootstrap, acquire, writer и cleanup продолжают same-operation recovery и не изображают release. Mismatch не снимает чужой lease, operational failure видим диагностике, recovery сохраняет operation и proposal identity, а writer допускается только по отдельному `GenerationWriterAdmissionOutcome / GRANTED` при пустом active set.

### FS_RESPONSE_OUTBOX_RECOVER

Изменение: pre-lease branch сначала читает outbox: `ABSENT` разрешает proposal, `TERMINAL_COMMITTED` даёт exact replay с исходным `NONE|lease_id` scope и прежней closure continuation, `OPEN` - `PRELEASE_OPEN_REPLAY_REQUIRED`; приоритетные `CORRUPT|UNAVAILABLE` обрабатывает только общий reject path. `NOT_COMMITTED|UNKNOWN` также не позволяют повторно сериализовать ответ. Каждый release-derived closure proposal встраивает полный `response_entry_mode_evidence`; digest покрывает каждое поле. В producing epoch live-confirm принимает только byte-identical mode; после crash отдельный persisted-readback transform читает из `TERMINAL_COMMITTED` то же самодостаточное значение и производит ноль нового live mode, не требует эфемерных proposal/mode outputs старой epoch либо скрытого lookup. Новый opposite mode не перепривязывает запись. Process-death proposal отдельно доказывается command identity. Supervisor выдаёт `RETRY` с прежней identity и только после bounded исчерпания - `EXHAUSTED`; тогда возникает внутренний `PublicSearchRecoveryBlocked`, но не public terminal/error. `UNAVAILABLE` не создаёт revision или `ABSENT`; generation ledger не является источником terminal bytes.

Доказательство: crash до/после OPEN, TERMINAL_COMMITTED, release response, closure proposal и closure commit, потерянный write ACK, unavailable primary/replay lookup, exact replay после смены поколения и повреждённый journal дают либо исходные immutable bytes/`SUPPRESSED`, либо типизированное recovery-состояние и bounded terminal block. Недоказанный proposal с opposite mode не меняет closure; persisted proposal замыкается по полному embedded mode evidence без liveness-разрыва или скрытого lookup; exact process-death command замыкает свой отдельный путь. Ни один сценарий не создаёт второй terminal, новый release key или ответ из текущего поколения.

### FS_SEARCH_REFINE_REQUEST

Изменение: пользователь заменяет запрос либо один из двух фильтров; корпус, модели и проекции не меняются. Если предел превышает один неизбежный фрагмент, маршрут останавливается до исправления источника владельцем корпуса.

Доказательство: новый запрос заново проходит общие ограничения, а успешный сериализованный ответ не превышает 131072 байта. Повтор прежнего ввода не выдаётся за восстановление.

### FS_RELEASE_CONNECT

Изменение: поставляемый Windows-артефакт запускается как локальный MCP-процесс с выбранной рабочей областью. Внутреннее состояние поиска не создаётся и не перестраивается скрыто.

Доказательство: контрольная сумма и происхождение относятся к точной редакции, совместимый клиент завершает инициализацию и видит только `search`, после чего воспроизводит маршрут `FS_SEARCH_EXECUTE`.

### FS_SOURCE_ANCHOR_HANDOFF

Изменение: FastSearch при построении `PublicSearchResult v2` создаёт `SearchSourceAnchor v1` для одной записи и одного захваченного `state_generation`. Выбор результата отдаёт уже созданную привязку и не делает lookup по текущему поколению. Постоянное состояние, ранжирование и граф не меняются. MCP либо JSON только сериализует общий формат; композиционный клиент передаёт его дальше без преобразования полей.

Доказательство DT13-A: независимый потребитель сопоставляет `contract_id`, `contract_version`, `workspace_id`, `contour`, `root_id`, относительный путь, полный selector payload, оба хэша и поколение с авторитетными источниками FastSearch. Недоступное происхождение, абсолютный путь или смешанное поколение запрещают публикацию v2; несовпадение точных байтов после публикации даёт потребительский `STALE_SOURCE_ANCHOR`.

Доказательство DT13-B: следующий владелец - совместимый профиль FastGraph - независимо допускает корень, проверяет `raw_source_sha256` по исходным байтам и создаёт собственную identity узла либо типизированный отказ. FastSearch не проверяет результат обхода и не подменяет отсутствующий consumer.

| Сценарий | Последовательность | Конечный результат |
|---|---|---|
| Готовая область и допустимый запрос | `FS_WORKSPACE_OPEN -> FS_SEARCH_EXECUTE` | `SUCCESS`, 0-6 результатов |
| Явный Public Search v2 | `FS_WORKSPACE_OPEN -> FS_SEARCH_EXECUTE_V2` | 0-6 базовых результатов с exactly-one anchor outcome |
| Неизвестная версия ответа | `FAILED / UNSUPPORTED_RESPONSE_VERSION` | Поиск не начался; доступны версии 1 и 2 |
| Область не выбрана | `NEEDS_CHOICE -> FS_WORKSPACE_OPEN -> FS_SEARCH_EXECUTE` | Выбранный объект и `SUCCESS` |
| Источники не настроены, модели уже готовы | `BLOCKED -> FS_SEARCH_CONFIGURE_SOURCES -> FS_SEARCH_REBUILD_PROJECTIONS -> FS_SEARCH_RETRY` | `SEARCH_READY`, затем `SUCCESS` |
| Модельная роль не готова | `BLOCKED -> FS_SEARCH_PREPARE_MODELS -> FS_SEARCH_RETRY` | Готовый набор, затем `SUCCESS` либо следующий точный блок |
| Индекс устарел | `BLOCKED / STALE_INDEX -> FS_SEARCH_UPDATE_PROJECTIONS -> FS_SEARCH_RETRY` | Новое согласованное поколение и `SUCCESS` |
| Поколение изменилось при сборке v2 | `FS_SEARCH_EXECUTE_V2(G1) -> update(G2) -> FAILED / STALE_INDEX -> FS_SEARCH_RETRY` | Один внешний отказ без partial response; новый вызов захватывает G2 либо называет необходимость rebuild |
| Revalidation или сборка v2 отказала после ranked bundle | `FS_SEARCH_EXECUTE_V2 -> FAILED / SEARCH_FAILED -> FS_SEARCH_RETRY` | Partial response подавлен; lease отсутствует либо освобождён после фиксации ошибки; повторный отказ направляет к диагностике source/state |
| Release после terminal временно не подтверждён | `terminal -> RELEASE_FAILED|NOT_COMMITTED_RETRY|COMMIT_READBACK_REQUIRED -> RECOVERY_REQUIRED -> FS_GENERATION_LEASE_RECOVER -> RELEASED|ALREADY_RELEASED / CLOSED` | Уже committed terminal/envelope сохранён; same-key bounded recovery продолжается; writer заблокирован до authoritative closure или process cleanup |
| Release уже committed, response outbox ещё не закрыт | `crash -> acquire REPLAYED_TERMINAL(released_revision) -> exact same-key release -> ALREADY_RELEASED -> CLOSED` | Новая release identity и второй envelope не создаются; outbox достигает closure по исходной операции |
| Coordinator response получен перед crash | `redelivery RELEASED|RELEASE_FAILED|commit status|state-access block -> RESTART_READBACK(restart_intent_ref) -> replay continuation -> closure proposal` | Finalized assembly и permit не требуются; response применяется ровно к retained terminal и mode |
| Crash после release-derived closure proposal | `proposal(response_entry_mode_evidence) -> restart -> TERMINAL_COMMITTED(last closure transition) | NOT_COMMITTED|UNKNOWN + opposite mode` | Отдельный persisted-readback без старых outputs или другого lookup восстанавливает `CLOSED|RECOVERY_REQUIRED|RECOVERY_BLOCKED` по полному embedded mode evidence; недоказанный proposal не меняет closure; process-death path отдельно использует command identity |
| Release recovery получил terminal block | `COMMIT_RECOVERY_BLOCKED|GenerationLeaseStateAccessBlocked -> RECOVERY_BLOCKED / PublicSearchRecoveryBlocked` | Следующий release request запрещён, включая переход из прежнего `RECOVERY_REQUIRED`; до durable blocked readback выполняется только same-proposal response-outbox recovery. Terminal сохранён, writer остаётся заблокирован; только независимый matching process-death cleanup может доказать `PROCESS_DIED_CLOSED`, после чего durable `ProcessDiedClosureAck` завершает delivery progress даже при lost ACK |
| Generation ledger потерян, повреждён или недоступен | `MISSING_PREVIOUS|CORRUPT|UNAVAILABLE -> BLOCKED / LEASE_LEDGER_RECOVERY_UNSPECIFIED` | Bootstrap и source rebuild не запускаются; существующие lease/writer identities не считаются пустыми; операторское восстановление заблокировано до отдельного контракта |
| Response outbox commit или terminal journal не доказан | `NOT_COMMITTED|UNKNOWN|CORRUPT|UNAVAILABLE|PRELEASE_OPEN_REPLAY_REQUIRED -> FS_RESPONSE_OUTBOX_RECOVER -> exact readback | EXHAUSTED / OPERATOR_RECOVERY_UNSPECIFIED` | Не создан второй terminal, delivery или release; текущая generation не используется для реконструкции; после bounded stop операторский repair не определён |
| Старая схема до DT13-A | `BLOCKED -> FS_SOURCE_PROVENANCE_REBUILD -> FS_SEARCH_REBUILD_PROJECTIONS -> FS_SEARCH_RETRY` | Атомарный новый source/provenance bundle и согласованные проекции; частичная миграция не использована |
| Очередь заполнена | `BLOCKED / BUSY -> FS_SEARCH_RETRY` | Новый вызов после освобождения места |
| Запрос отменён | `FS_SEARCH_CANCEL` | `CANCELLED`, состояние поиска сохранено |
| Ответ превышает предел | `FAILED / RESPONSE_TOO_LARGE -> FS_SEARCH_REFINE_REQUEST -> FS_SEARCH_EXECUTE` | Ограниченный ответ либо точный `BLOCKED` на исправление источника |
| Выпуск из чистого каталога | `FS_RELEASE_CONNECT -> FS_SEARCH_EXECUTE` | Подключённый инструмент воспроизводит `USR-FS-03` |
| Привязка готова, внешний resolver отсутствует | `FS_SEARCH_EXECUTE_V2 -> BLOCKED / GRAPH_RESOLVER_UNAVAILABLE` | Поиск сохранён; назван владелец внешнего блокера |
| FastSearch не может произвести поддерживаемую версию или полный selector payload | `FS_SEARCH_EXECUTE_V2 -> BLOCKED / UNSUPPORTED_SOURCE_ANCHOR` | Привязка не создана; базовый результат сохранён; владельцем обновления назван FastSearch |
| Существующая привязка не поддерживается потребителем | `FS_SEARCH_EXECUTE_V2 -> BLOCKED / UNSUPPORTED_SOURCE_ANCHOR` | Привязка и базовый результат сохранены; владельцем обновления назван клиент либо FastGraph |
| Источник изменился после ответа G1 | `FS_SEARCH_EXECUTE_V2(G1) -> update(G2) -> FS_SOURCE_ANCHOR_HANDOFF -> BLOCKED / STALE_SOURCE_ANCHOR` | Привязка G1 не переписана; выполняется новый поиск G2 |
| Сквозная композиция готова | `FS_SEARCH_EXECUTE_V2 -> FS_SOURCE_ANCHOR_HANDOFF -> FastGraph resolve-anchor -> GraphProvider traverse` | Точный узел закреплённой ревизии либо типизированный отказ владельца |

## Неизвестности

| Вопрос | Влияние | Когда закрывается |
|---|---|---|
| Форма постоянной регистрации поставляемого MCP-процесса в конкретном клиенте | Только `FS_RELEASE_CONNECT`; поисковая семантика не меняется | До материализации DT4-E по выбранному клиенту и выпускному профилю |
| Имя и выход capability-профиля FastGraph | Только внешний участок после `FS_SOURCE_ANCHOR_HANDOFF`; поля привязки FastSearch не меняются | В канонической потребляющей паре FastGraph до DT13-B |
| Владелец и способ поставки композиционного клиента | Определяет пользовательскую точку входа DT13-B, но не ownership данных | До детального планирования DT13-B |
