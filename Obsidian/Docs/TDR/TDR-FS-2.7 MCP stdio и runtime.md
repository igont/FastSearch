# TDR-FS-2.7 - MCP через stdio и владение средой исполнения

## Контекст и задача

FastSearch должен предоставить один локальный MCP-инструмент без дублирования поисковой логики. Протокольный цикл асинхронен, а модельные адаптеры тяжёлые и не должны неявно получать параллельное владение.

## Поддерживаемые парадигмы

[FastSearch как поисковый контур](<../../Paradigms/Архитектура/02 FastSearch как поисковый контур.md>) требует общий результат для JSON и MCP. [Терминальный интерфейс](<../../Paradigms/Архитектура/Рабочие области и интерфейс/02 Terminal-first интерфейс.md>) отделяет машинный ответ от консольного оформления.

## Входы и результаты

Входом служит MCP-вызов `search` с полями `query`, `project_scope` и `document_status`. Результатом служит тот же `PublicSearchResponse`, который сериализует `--json`. Протокольный слой не принимает пути моделей, выбор модели, режим ранжирования, команды индексации или другие инструменты.

## Решение

В тот же исполняемый файл добавляется режим `fastsearch mcp`. Сервер использует официальный [Rust SDK `rmcp 3.1.4`](https://github.com/modelcontextprotocol/rust-sdk/releases/tag/rmcp-v3.1.4) с серверным `stdio`-транспортом и закреплённым `Cargo.lock`. Контракт DT4 поддерживает MCP `2025-11-25` и цикл `initialize -> notifications/initialized`. Если клиент запрашивает другую версию, сервер отвечает своей поддерживаемой `protocolVersion: 2025-11-25`; несовместимый клиент должен разорвать соединение и не переходить к обычным операциям. Расширение списка поддерживаемых версий требует отдельной квалификации и не входит в DT4.

Штатный запуск имеет одну форму: `fastsearch mcp --workspace <абсолютный-каталог>`. Относительный, отсутствующий или повторно переданный путь является ошибкой использования до начала протокольного обмена. Процесс открывает `.fastsearch/workspace.toml` через `WorkspaceStore`, получает из него документальные и кодовые корни, а служебный корень выводит как `<workspace>/.fastsearch/local`. Каждая из трёх проекций находится только в `<workspace>/.fastsearch/local/index/vector/<model-slug>/<model-revision>`; редакция каталога должна точно совпадать с закреплённой редакцией роли, а все три проекции - с одним поколением корпуса. Проверенный машинный каталог четырёх модельных ролей читается из штатного `FASTSEARCH_HOME`, а при его отсутствии - из системного каталога FastSearch. Других переменных путей режим MCP не принимает.

`WorkspaceStore::production_config()` расширяется списком трёх закреплённых векторных ролей и ролью Qwen; он остаётся единственным производителем `ProductionConfig`. Запуск MCP не создаёт рабочую область, не подменяет корни, не скачивает модели и не строит проекции: неготовое штатное состояние возвращает `NOT_READY`.

`stdout` содержит только MCP-сообщения. Диагностика пишется в `stderr` без путей кэша, внутренних оценок и содержимого корпуса сверх публичного ответа. Закрытие `stdin` завершает приём новых вызовов и приводит к управляемому завершению процесса.

## Владение и параллельность

Протокольный цикл работает в Tokio, а один выделенный рабочий поток единолично владеет `ProductionRuntime` и координатором моделей. Между ними находится ограниченная очередь: один внешний запрос выполняется, один может ожидать, остальные получают типизированную ошибку занятости. Запрет параллельности относится к внешним запросам. Внутри одного запроса координатор может одновременно открыть три адаптера моделей эмбеддингов для поиска кандидатов, обязан объединить результаты и освободить их до открытия Qwen. Так сохраняются единственный владелец запроса, ограниченная внутренняя параллельность и отсутствие перекрытия Qwen с моделями эмбеддингов.

Отмена помечает вызов как неактуальный и прекращает его на ближайшей безопасной границе между этапами поиска. Если один модельный вызов уже выполняется и не поддерживает прерывание, его результат отбрасывается. Запрос не изменяет индексы, поэтому отмена не требует отката состояния.

## Ошибки и восстановление

Ошибки формата, неизвестный инструмент и нарушение протокольного цикла возвращаются как MCP-ошибки. Ожидаемые ошибки поиска возвращают результат инструмента с `isError: true` и структурой `error { code, message, retryable }`. Сообщение не содержит абсолютные пути служебного состояния, внутренние оценки, стек или текст соседних записей.

После ошибки поиска среда исполнения остаётся доступна для следующего вызова, если ошибка не обозначает потерю её инвариантов. Паника, потеря рабочего потока или неожиданное завершение сервера завершают процесс; клиент запускает его заново.

| Внутренняя причина | Публичный код | Повтор допустим | MCP-носитель |
|---|---|---|---|
| Пустой запрос, неизвестный фильтр, превышение принятой длины | `INVALID_REQUEST` | нет | результат инструмента, `isError: true` |
| Неготовая модель или проекция | `NOT_READY` | да, после подготовки | результат инструмента, `isError: true` |
| Устаревшее поколение индекса | `STALE_INDEX` | да, после обслуживания | результат инструмента, `isError: true` |
| Активный и ожидающий запрос уже заняли очередь | `BUSY` | да | результат инструмента, `isError: true` |
| Превышено принятое время | `TIMEOUT` | да | результат инструмента, `isError: true` |
| Ответ превышает принятый размер | `RESPONSE_TOO_LARGE` | нет без изменения запроса или корпуса | результат инструмента, `isError: true` |
| Ошибка чтения, модели или координатора без потери инвариантов | `SEARCH_FAILED` | да | результат инструмента, `isError: true` |
| Неизвестный инструмент или неверная структура JSON-RPC | код протокола | зависит от причины | MCP-ошибка |
| Клиент запросил неподдерживаемую версию MCP | сервер отвечает `protocolVersion: 2025-11-25`; несовместимый клиент завершает соединение | только новым совместимым соединением | ответ `initialize`, без перехода к операциям |
| Уведомление об отмене | публичный ответ не отправляется | да новым вызовом | завершение отменённого вызова по протоколу |

## Инварианты

- MCP-адаптер не содержит поисковой или ранжирующей логики.
- Один вызов видит одно поколение корпуса и три актуальные проекции.
- Одна среда исполнения одновременно обрабатывает не более одного внешнего поиска.
- Публичный JSON и структурный MCP-результат семантически равны.
- Запрос не запускает подготовку моделей, индексацию или перестроение.

## Рассмотренные варианты

Самостоятельная реализация JSON-RPC уменьшила бы число зависимостей, но передала бы FastSearch ответственность за согласование версий, границы сообщений, отмену и цикл жизни. Официальный SDK сокращает эту протокольную поверхность и имеет готовый `stdio`-транспорт.

Многопоточное общее владение средой исполнения могло бы увеличить пропускную способность, но до измерений оно не имеет основания и усложняет владение моделями. Поэтому первая производственная граница последовательна.

## Последствия и ограничения

`Cargo.toml` получает `rmcp`, Tokio и генерацию JSON Schema. Тяжёлые вычисления не занимают асинхронный цикл. Первая версия не обещает параллельную обработку внешних запросов, HTTP, авторизацию и возможности MCP `resources`, `prompts` или `tasks`.

## Связи и основания

[TDR-FS-2](<TDR-FS-2 Workspaces и terminal UX.md>) определяет пакет. [TDR-FS-2.3](<TDR-FS-2.3 Terminal routing и terminal-dialogue.md>) отделяет машинное представление. [TDR-FS-2.4](<TDR-FS-2.4 Automatic model provisioning.md>) задаёт готовность моделей. [TDR-FS-2.6](<TDR-FS-2.6 Единый поиск и переранжирование.md>) задаёт вход и публичный ответ.

Владельцем прикладной границы станет новый модуль публичного поиска в `src/application`, а MCP-адаптер будет размещён в `src/adapters`. Точка входа `src/main.rs` выбирает режим, но не содержит логику инструмента.

## Проверка решения

Реальный MCP-клиент запускает исполняемый файл выпуска, согласует версию, видит только `search`, выполняет запрос и сравнивает структурный ответ с JSON-ответом того же приложения. Отдельные проверки подтверждают чистый `stdout`, закрытие по EOF, отмену, переполнение очереди и очистку ошибок.

## Термины

`stdio`-транспорт - локальный обмен MCP-сообщениями через стандартные потоки дочернего процесса. Runtime - долгоживущая среда выполнения с открытым состоянием рабочей области. SDK - официальный комплект разработки протокольного адаптера. DTO - отдельный тип данных публичной границы. Владелец runtime - единственный поток, который принимает внешние запросы и управляет внутренними модельными заданиями.
