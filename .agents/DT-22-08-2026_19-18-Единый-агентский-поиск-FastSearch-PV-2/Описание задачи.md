## Тонкий сквозной проход `TS-DT4-01`

Среда прохода - Windows x86_64, закреплённые в `rust-toolchain.toml` `rustc 1.95.0` и `cargo 1.95.0`, исполняемый файл выпуска и клиент `rmcp 3.1.4` в режиме MCP `2025-11-25`. A2 до начала A5 создаёт и фиксирует `evidence/dt4/fixtures/ts-dt4-01/corpus-manifest.json`, `startup-manifest.json`, `query.txt`, `model-manifest.json` и `oracle.json`. Перечень корпуса содержит ровно десять Markdown-фрагментов без явных фильтров, SHA-256 каждого содержимого и одно поколение корпуса. `startup-manifest.json` закрепляет шаблоны `workspace/.fastsearch/workspace.toml`, штатного `.fastsearch/local` с каноническим состоянием и каталогами трёх проекций вида `index/vector/<model-slug>/<model-revision>`, а также содержимого `product-home` с проверенными манифестами четырёх ролей. Для каждой проекции он хранит точную редакцию модели и поколение корпуса; все три редакции совпадают с `model-manifest.json`, а поколения равны. Перечень моделей содержит репозитории, редакции и SHA-256 Arctic, E5 Large, Nomic и Qwen. Файл запроса содержит одну строку UTF-8 `автоматическая подготовка локальных моделей` с LF.

Независимый Python-контур до A5 строит для каждой модели эмбеддингов массив из шести `{stable_id, rank}`, затем ожидаемый массив после удаления повторов, вероятности Qwen и итоговые шесть `{rank, stable_id, title, normalized_path, project_scope, document_status, content_sha256}`. Он независимо реализует закреплённые в TDR-FS-2.4 префиксы, пределы токенов, пулинг, размерность и L2-нормализацию Arctic, E5 Large и Nomic; изменение этого контракта аннулирует оракул. Скрипт находится в `scripts/dt4_oracle.py`; среда закреплена как CPython `3.13.14`. Файл `evidence/dt4/oracle/requirements.lock` закрепляет с хешами полный граф зависимостей, включая `torch 2.7.1`, `transformers 4.53.3`, `safetensors 0.5.3`, `tokenizers 0.21.2` и `numpy 2.3.2`. Точные команды подготовки: `python --version`, затем `python -m pip install --require-hashes -r evidence/dt4/oracle/requirements.lock` с требованием точного вывода `Python 3.13.14` у первой команды. Точная команда построения: `python scripts/dt4_oracle.py --fixture-root evidence/dt4/fixtures/ts-dt4-01 --output evidence/dt4/fixtures/ts-dt4-01/oracle.json`. `oracle.json` имеет `schema: 1`, точные хеши скрипта, файла зависимостей, корпуса, моделей и запроса; он не читает результат Rust-цепочки. Значения по умолчанию равны `general` и `actual`.

Точные команды основного прохода: `rustup run 1.95.0 cargo build --release --locked` и `rustup run 1.95.0 cargo test --locked --test dt4_mcp_thin_slice -- --ignored --exact mcp_search_crosses_three_projections_and_qwen`. Тестовый каркас получает только четыре переменные: `FASTSEARCH_DT4_FIXTURE_ROOT` - абсолютный каталог набора данных, `FASTSEARCH_DT4_MODEL_CACHE` - абсолютный каталог шаблона машинного кэша, `FASTSEARCH_DT4_ORACLE` - абсолютный путь `oracle.json`, `FASTSEARCH_DT4_EVIDENCE_OUT` - абсолютный путь итогового JSON. Каркас канонизирует и проверяет их хеши, создаёт временный каталог, копирует туда стандартные шаблоны `workspace` и `product-home`, повторно проверяет `startup-manifest.json`, точные редакции каталогов трёх проекций и единое поколение, назначает дочернему процессу текущим каталогом абсолютный корень временной рабочей области и запускает `target/release/fastsearch.exe mcp --workspace <тот-же-абсолютный-корень>`. Дочерний процесс не получает ни одной `FASTSEARCH_DT4_*`; из путевых переменных он получает только штатную `FASTSEARCH_HOME=<временный-product-home>`. Документальные и кодовые корни читаются из `.fastsearch/workspace.toml`, а служебный и три векторных корня с редакциями моделей выводятся из штатного `.fastsearch/local`. PASS реального MCP-прохода сравнивает с `oracle.json` только публичные шесть результатов, ошибки и порядок, подтверждает отсутствие оценок и происхождения кандидатов и записывает разрешённые пути, хеши, редакции проекций и поколение в `FASTSEARCH_DT4_EVIDENCE_OUT`.

Промежуточные массивы проверяются отдельно, без изменения производственной границы: `rustup run 1.95.0 cargo test --locked --lib -- --ignored --exact application::unified_search::tests::three_projection_candidates_match_independent_oracle`. Закрытый `#[cfg(test)]`-наблюдатель прикладного координатора получает три массива `{stable_id, rank}`, массив после удаления повторов и вероятности Qwen, сравнивает их с соответствующими секциями `oracle.json` и не компилируется в исполняемый файл выпуска. Этот тест обязан пройти до основного MCP-прохода; `stdout`, MCP DTO и производственный `PublicSearchResponse` промежуточные данные не раскрывают.

Отдельные точные команды: `rustup run 1.95.0 cargo test --locked --test dt4_mcp_thin_slice -- --ignored --exact cancelled_call_emits_no_late_response`, `rustup run 1.95.0 cargo test --locked --test dt4_mcp_thin_slice -- --ignored --exact eof_stops_server` и `rustup run 1.95.0 cargo test --locked --test dt4_mcp_thin_slice -- --ignored --exact third_call_is_busy`. Окна ожидания берутся только из принятого `G-LIMITS` и записываются в доказательства теста.

Проверка отмены использует управляемый тестовый адаптер на той же очереди и границе ответа, удерживает непрерываемый модельный этап, отправляет отмену, затем явно освобождает этап и ждёт его фактический сигнал завершения. После этого она дочитывает сообщения до управляемого закрытия сеанса и доказывает, что идентификатор отменённого запроса ни разу не появился в ответе. Проверка EOF закрывает `stdin` и требует код завершения 0 в принятом окне. Проверка занятости удерживает один активный и один ожидающий запрос, а третий получает `BUSY` с `retryable: true` в принятом окне. Эти управляемые проверки не заменяют реальную модельную цепочку основного прохода. Любое расхождение закрывает `GA-FOUNDATION`.
