# A1 Performance contract

Release-mode benchmark uses five cold and five warm samples on the parameterized document root. Acceptance budgets: rebuild median <= 12,000 ms, rebuild max <= 18,000 ms; unchanged update median <= 5,000 ms, max <= 8,000 ms; warm exact query median <= 250 ms, max <= 500 ms; service bytes <= 2.0 x source bytes. DT2/A1 regression ratios: rebuild <= 1.40, update <= 1.40, warm query <= 1.50, service bytes <= 1.50, peak memory <= 1.50. A sample outside a budget is a gate failure, not an averaged-away outlier.

`warm exact query max <= 500 ms` is exclusively a pure in-process measurement: the process and store are already open before the timed query. E2's new-process reopen+query measurement is a different kind that includes Windows process startup, store reopen and one query; its maximum is `<= 750 ms`. Measurement kinds are not interchangeable and failed samples are never discarded. The original new-process series `270.126, 353.159, 575.127, 540.506, 261.237 ms` is retained as `FAILED_UNDER_WRONG_IN_PROCESS_500_MS_CLASSIFICATION`; its maximum is `575.127 ms`. The second new-process series is retained with observed maximum `282.027 ms` as `PASS_NEW_PROCESS_REOPEN_QUERY_750_MS`. The amendment corrects classification only; it does not remove or rewrite any sample.

Memory authority is split by process role. The non-vector FastSearch/DT2/A1 process peak working set must be <= 1,024 MiB. A local embedding provider child process has a separate peak working-set ceiling of <= 2,048 MiB on the measured 32 GiB workstation. Neither ceiling can borrow unused capacity from the other. Static model artifact bytes are recorded as a diagnostic and are not charged to either working-set gate; they are not capped by this contract. `manifest.json` is the machine-readable authority for these exact limits and latency kinds. `spikes/dt3-foundation/resource-budget.ps1` accepts the exact memory and latency boundaries and rejects each boundary plus one unit for its correct measurement kind.
